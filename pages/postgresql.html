Asosiy PostgreSQL Mavzu #1

PostgreSQL Nima? Dunyodagi Eng Ilg'or Relyatsion Baza

PostgreSQL (Postgres) — dunyodagi eng kuchli, ishonchli va kengaytiriluvchi ochiq kodli ob'ekt-relyatsion ma'lumotlar bazasi boshqaruv tizimidir (ORDBMS). U 35 yildan ortiq davr mobaynida faol rivojlantirilib kelinmoqda va moliyaviy barqarorlik, ma'lumotlar yaxlitligi (ACID) hamda boy imkoniyatlari bilan mashhur.

  • SQL standartlariga eng yuqori darajada mos keluvchi tizim (SQL:2023).
  • Ikkala dunyo afzalligi: ham qat'iy relyatsion jadvallar, ham JSONB orqali NoSQL hujjatsiz imkoniyatlar.
  • Apple, Reddit, Instagram, Spotify, NASA kabi yirik tashkilotlar asosiy baza sifatida Postgres dan foydalanadi.
  • Cheksiz kengayuvchanlik: PostGIS (geografik xaritalar), pgvector (Sun'iy intellekt vektor qidiruvi), TimescaleDB.
PostgreSQL / psql 
-- PostgreSQL versiyasi va server vaqtini tekshirish
SELECT 
    version() AS postgres_versiyasi,
    current_setting('server_version') AS qisqa_versiya,
    NOW() AS hozirgi_vaqt;

psql PostgreSQL Mavzu #3

psql — Terminal Konsol Vositasida Ishlash

psql — PostgreSQL ning tezkor buyruqlar satri (CLI) vositasidir. Tajribali dasturchilar va DevOps muhandislari bazani to'liq psql orqali boshqaradi.

  • Ulanish: psql -U postgres -d postgres.
  • Foydali meta-buyruqlar:
  • \l — barcha bazalar ro'yxatini ko'rish (List databases).
  • \c baza_nomi — ko'rsatilgan bazaga ulanish (Connect).
  • \dt — joriy bazadagi barcha jadvallar (Display tables).
  • \d jadval_nomi — jadval ustunlari va turlarini ko'rish (Describe).
  • \q — psql dan chiqish (Quit).
PostgreSQL / psql 
# psql ga kirish:
psql -U postgres

# Yangi baza yaratish va ulanish:
postgres=# CREATE DATABASE w3learn;
CREATE DATABASE
postgres=# \c w3learn
You are now connected to database "w3learn" as user "postgres".
w3learn=# \dt

💡 psql buyruqlari teskari slesh \ bilan boshlanadi va ularning oxiriga nuqta-vergul qo'yish shart emas.

DDL PostgreSQL Mavzu #4

CREATE TABLE — SERIAL, BIGSERIAL va UUID

PostgreSQL da jadvallar yaratishda avtomatik o'suvchi ID larni belgilash uchun qulay SERIAL, katta loyihalar uchun BIGSERIAL yoki xavfsiz va tarqatilgan tizimlar uchun UUID ishlatiladi.

  • SERIAL: 4-baytli butun son (1 dan 2 milliardgacha).
  • BIGSERIAL: 8-baytli ulkan son.
  • UUID: 128-bitli noyob global identifikator (tahmin qilib bo'lmaydi).
  • Zamonaviy standart sintaksis: id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY.
PostgreSQL / psql 
CREATE TABLE mijozlar (
    id BIGSERIAL PRIMARY KEY,
    mijoz_uuid UUID DEFAULT gen_random_uuid(),
    ism VARCHAR(60) NOT NULL,
    email VARCHAR(120) UNIQUE NOT NULL,
    balans NUMERIC(15, 2) DEFAULT 0.00,
    yaratilgan_sana TIMESTAMPTZ DEFAULT NOW()
);
🐘 PostgreSQL 16 Server Natijasi:
⚡ TIMESTAMPTZ — vaqt mintaqasini (Timezone) hisobga oluvchi sana turi bo'lib, xalqaro ilovalar uchun doimo TIMESTAMP o'rniga ishlatiladi.

DDL PostgreSQL Mavzu #5

ALTER TABLE — Jadvalni O'zgartirish

Mavjud jadvalga yangi ustun qo'shish, ustun nomini yoki turini o'zgartirish uchun ALTER TABLE ishlatiladi.

  • Yangi ustun: ALTER TABLE mijozlar ADD COLUMN telefon VARCHAR(25);.
  • Ustun turini o'zgartirish: ALTER TABLE mijozlar ALTER COLUMN ism TYPE VARCHAR(100);.
  • Standart qiymat berish: ALTER TABLE mijozlar ALTER COLUMN balans SET DEFAULT 10000;.
  • Ustunni o'chirish: ALTER TABLE mijozlar DROP COLUMN telefon;.
PostgreSQL / psql 
ALTER TABLE mijozlar 
ADD COLUMN IF NOT EXISTS status VARCHAR(20) DEFAULT 'faol';

-- Ustun nomini o'zgartirish
ALTER TABLE mijozlar 
RENAME COLUMN yaratilgan_sana TO created_at;

💡 PostgreSQL da ustun nomini o'zgartirish (RENAME COLUMN) barcha bog'liq indeks va ko'rinishlarni avtomatik yangilaydi.

DDL PostgreSQL Mavzu #6

DROP TABLE va CASCADE

Jadvalni o'chirish uchun DROP TABLE ishlatiladi. Agar boshqa jadvallar unga Foreign Key orqali bog'langan bo'lsa, Postgres xatolik beradi va o'chirishga yo'l qo'ymaydi. Majburiy o'chirish uchun CASCADE qo'shiladi.

  • Xavfsiz o'chirish: DROP TABLE IF EXISTS jadval_nomi;.
  • Bog'liqliklari bilan birga o'chirish: DROP TABLE buyurtmalar CASCADE;.
  • Jadvalni bo'shatish: TRUNCATE TABLE mijozlar RESTART IDENTITY; (ID hisoblagich ham 1 ga qaytadi).
PostgreSQL / psql 
-- Barcha bog'liqliklari bilan o'chirish
DROP TABLE IF EXISTS eski_buyurtmalar CASCADE;

-- Ma'lumotlarni tozalab ID ni 1 ga qaytarish
TRUNCATE TABLE loglar RESTART IDENTITY;
🐘 PostgreSQL 16 Server Natijasi:
🔒 CASCADE orqali jadval o'chirilganda unga bog'liq bo'lgan barcha VIEW va cheklovlar ham birga o'chib ketadi.

Unumdorlik PostgreSQL Mavzu #7

PostgreSQL Indekslari — B-Tree, GIN, GiST va BRIN

PostgreSQL dunyodagi eng boy indekslar to'plamiga ega. Oddiy sonlar, matnlar, JSON, massivlar va geografik nuqtalar uchun alohida optimallashgan indeks turlari mavjud.

  • B-Tree: Standart indeks turi. Qidiruv, saralash, <, >, = uchun O(log N) tezlik.
  • GIN (Generalized Inverted Index): JSONB, massivlar va Full-Text qidiruv uchun eng kuchli indeks.
  • GiST: Geografik xaritalar (koordinatalar, poligonlar) va oraliqlar uchun.
  • BRIN: Gigabaytlab vaqt ketma-ketligidagi (Time-series) ma'lumotlar uchun o'ta ixcham indeks.
PostgreSQL / psql 
-- B-Tree indeksi (Email qidiruvi uchun)
CREATE INDEX idx_mijozlar_email ON mijozlar(email);

-- Qisman indeks (Partial Index) - faqat faol mijozlarni indekslash (Xotirani 80% tejaydi!)
CREATE INDEX idx_faol_mijozlar ON mijozlar(email) WHERE status = 'faol';
🐘 PostgreSQL 16 Server Natijasi:
🚀 Qisman indeks (Partial Index) PostgreSQL ning ajoyib ustunligidir: u butun jadvalni emas, faqat WHERE shartiga mos qatorlarni indekslab xotirani va tezlikni tejaydi.

Xavfsizlik PostgreSQL Mavzu #8

Cheklovlar (Constraints) — Ma'lumotlar Butunligi

Cheklovlar ma'lumotlar bazasiga noto'g'ri, mantiqsiz yoki zararli ma'lumotlar kiritilishining oldini oladi.

  • PRIMARY KEY: Yagona va NOT NULL bo'lish sharti.
  • FOREIGN KEY (fk) REFERENCES ota_jadval(id) ON DELETE CASCADE: jadvallar o'rtasidagi mustahkam aloqa.
  • CHECK (balans >= 0): qiymat shartga to'g'ri kelishini tekshirish.
  • UNIQUE: takrorlanmaslik kafolati.
PostgreSQL / psql 
CREATE TABLE hisoblar (
    id SERIAL PRIMARY KEY,
    egasi_id BIGINT REFERENCES mijozlar(id) ON DELETE CASCADE,
    valyuta VARCHAR(3) CHECK (valyuta IN ('UZS', 'USD', 'EUR')),
    balans NUMERIC(14, 2) CHECK (balans >= 0)
);
🐘 PostgreSQL 16 Server Natijasi:
💡 CHECK cheklovi backend kodida xatolik yuz berganda ham ma'lumotlar bazasi darajasida manfiy balans kabi xatolarning oldini oladi.

DML PostgreSQL Mavzu #9

INSERT va ON CONFLICT (Upsert) Imkoniyati

PostgreSQL da yangi qator kiritishda agar ma'lumot allaqachon mavjud bo'lsa (masalan email takrorlansa), xatolik bermasdan mavjud qatorni yangilash yoki o'tkazib yuborish imkonini beruvchi kuchli ON CONFLICT (Upsert) mexanizmi mavjud.

  • Oddiy qo'shish: INSERT INTO mijozlar (ism, email) VALUES ('Akmal', 'akmal@uz');.
  • Natijani bir zumda qaytarish: RETURNING *;.
  • Upsert (To'qnashganda yangilash): ON CONFLICT (email) DO UPDATE SET ism = EXCLUDED.ism;.
  • To'qnashganda o'tkazib yuborish: ON CONFLICT (email) DO NOTHING;.
PostgreSQL / psql 
-- RETURNING orqali yangi yaratilgan ID ni darhol olish:
INSERT INTO mijozlar (ism, email, balans)
VALUES ('Akmal', 'akmal@uz', 500000)
ON CONFLICT (email) 
DO UPDATE SET balans = mijozlar.balans + EXCLUDED.balans
RETURNING id, ism, email, balans;
🐘 PostgreSQL 16 Server Natijasi:
🚀 RETURNING id tufayli alohida yana bitta SELECT so'rovi yubormasdan turib yangi qo'shilgan qatorning ID sini bir vaqtning o'zida olishingiz mumkin.

DQL PostgreSQL Mavzu #10

SELECT va DISTINCT ON — Ilg'or Tanlash

PostgreSQL standart SQL SELECT imkoniyatlarini o'ziga xos DISTINCT ON operatori bilan boyitadi.

  • DISTINCT ON (ustun) — har bir guruhdan faqat birinchi eng yangi yoki eng katta bitta qatorni tanlab olish.
  • Klassik LIMIT va OFFSET orqali sahifalash.
  • Matnlarni chiroyli ulash: ism || ' ' || email.
PostgreSQL / psql 
-- Har bir mijozning eng oxirgi bitta buyurtmasini topish
SELECT DISTINCT ON (mijoz_id) 
    mijoz_id, 
    id AS buyurtma_id, 
    summa, 
    created_at
FROM buyurtmalar
ORDER BY mijoz_id, created_at DESC;
🐘 PostgreSQL 16 Server Natijasi:
💡 DISTINCT ON faqat PostgreSQL da mavjud bo'lgan noyob xususiyat bo'lib, boshqa bazalarda buning uchun og'ir Window funksiyalar yozishga to'g'ri keladi.

DML PostgreSQL Mavzu #11

UPDATE va RETURNING

Postgres da UPDATE buyrug'i ham RETURNING ni qo'llab-quvvatlaydi, bu orqali yangilangan qatorlarning yangi qiymatlarini darhol qaytarib olish mumkin.

  • Sintaksis: UPDATE mijozlar SET balans = balans + 10000 WHERE id = 1 RETURNING *;.
  • Bir nechta jadvallarni bir vaqtda yangilash (UPDATE FROM).
PostgreSQL / psql 
UPDATE mijozlar
SET balans = balans * 1.05 -- 5% bonus qo'shish
WHERE status = 'faol'
RETURNING id, ism, balans AS yangi_balans;

JOIN PostgreSQL Mavzu #13

PostgreSQL JOIN Turlari va CROSS JOIN

PostgreSQL relyatsion jadvallarni bog'lashning barcha standart turlarini (INNER, LEFT, RIGHT, FULL OUTER) va har bir qatorni har bir qatorga ko'paytiruvchi CROSS JOIN (Dekart ko'paytma) ni qo'llab-quvvatlaydi.

  • INNER JOIN: Ikkala tomonda ham mos kelganlar.
  • LEFT JOIN: Chap jadval to'liq saqlanadi.
  • FULL JOIN: Ikkala tomon ham to'liq birlashadi.
  • CROSS JOIN: Barcha mumkin bo'lgan kombinatsiyalarni hosil qilish.
PostgreSQL / psql 
-- Barcha o'lchamlar va ranglar kombinatsiyasini hosil qilish
SELECT o.olcham, r.rang
FROM (VALUES ('S'), ('M'), ('L')) AS o(olcham)
CROSS JOIN (VALUES ('Qizil'), ('Ko''k')) AS r(rang);
🐘 PostgreSQL 16 Server Natijasi:
💡 CROSS JOIN do'konlarda mahsulotlarning barcha variantlarini (o'lcham x rang) avtomatik generatsiya qilish uchun qulaydir.

Murakkab PostgreSQL Mavzu #14

Subquery va EXISTS / NOT EXISTS Operatorlari

Ichki so'rovlarda IN ga qaraganda EXISTS ancha tez ishlaydi, chunki u mos keluvchi birinchi qatorni topishi bilanoq qidiruvni to'xtatadi.

  • WHERE EXISTS (SELECT 1 FROM buyurtmalar WHERE ...).
  • Kamida bitta buyurtma bergan mijozlarni topish.
  • NOT EXISTS: Hech qachon buyurtma bermaganlarni topish.
PostgreSQL / psql 
-- Kamida 1 ta buyurtmasi bor mijozlar
SELECT ism, email
FROM mijozlar m
WHERE EXISTS (
    SELECT 1 
    FROM buyurtmalar b 
    WHERE b.mijoz_id = m.id AND b.summa > 100000
);
🐘 PostgreSQL 16 Server Natijasi:
⚡ Katta hajmdagi jadvallarda IN (SELECT ...) o'rniga doimo EXISTS ishlatish so'rovni 10 baravargacha tezlashtiradi.

CTE PostgreSQL Mavzu #15

CTE (Common Table Expressions) — WITH So'rovlari

CTE (WITH so'rovi) — murakkab va uzun SQL kodlarini o'qilishi oson, modulli va qismlarga bo'lingan vaqtinchalik jadvallar ko'rinishida yozish imkoniyatidir. Shuningdek, Recursive CTE orqali daraxtsimon (daraxt, menyu, xodimlar iyerarxiyasi) tuzilmalarni osongina aylanib chiqish mumkin.

  • Sintaksis: WITH vaqtinchalik_jadval AS (SELECT ...) SELECT * FROM vaqtinchalik_jadval;.
  • Kodning o'qilishini (readability) 100% yaxshilaydi.
  • Recursive CTE: o'z-o'zini chaqiruvchi iyerarxik so'rovlar.
PostgreSQL / psql 
-- O'rtacha hisobdan yuqori balansga ega mijozlar
WITH ortacha_balans AS (
    SELECT AVG(balans) AS ortacha FROM mijozlar
)
SELECT m.ism, m.balans, round(o.ortacha, 2) AS umumiy_ortacha
FROM mijozlar m, ortacha_balans o
WHERE m.balans > o.ortacha;
🐘 PostgreSQL 16 Server Natijasi:
🚀 Recursive CTE orqali ko'p pog'onali kategoriyalar (masalan Elektronika -> Smartfonlar -> Apple) ni bitta so'rovda to'liq iyerarxiya bilan chiqarish mumkin.

Window PostgreSQL Mavzu #16

Window Funksiyalari — ROW_NUMBER, RANK, DENSE_RANK

Window Funksiyalari — qatorlarni birlashtirib bitta qilib tashlamasdan (GROUP BY dan farqli ravishda), har bir qatorning o'z o'rnini saqlagan holda oynama-oyna (Window) hisob-kitoblar, reytinglar va o'tgan oydagi ko'rsatkichlar bilan solishtirish imkonini beradi.

  • ROW_NUMBER() OVER (ORDER BY ball DESC) — har bir qatorga tartib raqami berish.
  • RANK() va DENSE_RANK() — durang bo'lganda o'rinlarni hisoblash.
  • LAG() va LEAD() — oldingi va keyingi qator qiymatini solishtirish.
  • Guruhlar ichida alohida oynalar: PARTITION BY shahar.
PostgreSQL / psql 
-- Har bir shahar ichida eng katta balansga ega mijozlarni reytinglash
SELECT 
    ism, 
    shahar, 
    balans,
    ROW_NUMBER() OVER (PARTITION BY shahar ORDER BY balans DESC) AS shahar_reytingi
FROM mijozlar;
🐘 PostgreSQL 16 Server Natijasi:
💡 Window funksiyalari Data Analyst va FinTech sohasidagi eng qimmatli tahliliy vositalardir.

Guruhlash PostgreSQL Mavzu #17

Ilg'or Guruhlash — GROUPING SETS, ROLLUP va CUBE

PostgreSQL hisobotlarni bir necha o'lchamda bitta so'rov orqali yig'ish uchun ilg'or guruhlash operatorlarini taqdim etadi.

  • ROLLUP(yil, oy): yil, oy va umumiy jami (Grand Total) hisobotini bitta so'rovda chiqaradi.
  • CUBE(shahar, toifa): barcha mumkin bo'lgan kesimlardagi yig'indilarni hisoblaydi.
  • GROUPING SETS: faqat o'zingizga kerakli aniq kombinatsiyalar bo'yicha guruhlash.
PostgreSQL / psql 
SELECT 
    shahar, 
    status, 
    COUNT(*) AS soni,
    SUM(balans) AS jami_balans
FROM mijozlar
GROUP BY ROLLUP(shahar, status);
🐘 PostgreSQL 16 Server Natijasi:
⚡ Excel dagi 'Pivot Table' (Xulosa jadvallari) xuddi shu ROLLUP va CUBE asosida ishlaydi.

JSONB PostgreSQL Mavzu #18

JSONB — PostgreSQL da NoSQL Imkoniyatlari

PostgreSQL da JSONB (Binary JSON) ma'lumot turi mavjud. U MongoDB kabi moslashuvchan JSON hujjatlarni saqlash, ularning ichki maydonlarini qidirish va hattoki GIN indekslar orqali chaqmoqdek tez tahlil qilish imkonini beradi.

  • Maydon qiymatini matn sifatida olish: meta->>'shahar'.
  • Ichki JSON ob'ektni olish: meta->'manzil'.
  • Kalit mavjudligini tekshirish: meta ? 'email'.
  • GIN indeksi orqali JSON ichidagi har qanday maydonni to'liq indekslash.
PostgreSQL / psql 
-- JSONB ustunli jadval yaratish
CREATE TABLE buyurtmalar_json (
    id SERIAL PRIMARY KEY,
    detallar JSONB
);

-- Ma'lumot qo'shish
INSERT INTO buyurtmalar_json (detallar)
VALUES ('{"mijoz": "Ali", "buyumlar": ["Noutbuk", "Sichqoncha"], "summa": 8500000}');

-- JSON ichidan maydonni o'qish
SELECT 
    detallar->>'mijoz' AS mijoz_ismi,
    detallar->'buyumlar'->>0 AS birinchi_buyum
FROM buyurtmalar_json;
🐘 PostgreSQL 16 Server Natijasi:
🚀 JSONB tufayli ko'plab loyihalarda alohida MongoDB o'rnatish zaruriyati qolmaydi — PostgreSQL har ikkala vazifani mukammal uddalaydi!

Tiplar PostgreSQL Mavzu #19

Array (Massiv) Ma'lumot Turlari

PostgreSQL har qanday ma'lumot turidan massiv yaratishga ruxsat beradi: INTEGER[], TEXT[] va h.k.

  • Massiv e'lon qilish: teglar TEXT[].
  • Qo'shish: ARRAY['postgres', 'sql', 'backend'].
  • Element mavjudligini tekshirish: 'postgres' = ANY(teglar).
  • Massivni alohida qatorlarga yoyish: unnest(teglar).
  • Qatorlarni massivga yig'ish: array_agg(ism).
PostgreSQL / psql 
SELECT 
    ARRAY['Dushanba', 'Seshanba', 'Chorshanba'] AS haftaning_boshi,
    unnest(ARRAY[10, 20, 30]) AS qatorlarga_yoyilgan;
🐘 PostgreSQL 16 Server Natijasi:
💡 Bitta yozuvga tegishli teglar yoki telefon raqamlarini alohida jadvallarsiz to'g'ridan-to'g'ri massivda saqlash mumkin.

Qidiruv PostgreSQL Mavzu #20

Full-Text Qidiruv — tsvector va tsquery

PostgreSQL so'zlarning o'zaklarini tushunuvchi, xatolarni hisobga oluvchi va so'zlar ahamiyati bo'yicha saralovchi o'rnatilgan Full-Text Search (To'liq matnli qidiruv) dvigateliga ega.

  • to_tsvector('english', matn): matnni so'z o'zaklariga (lexemes) ajratadi.
  • to_tsquery('english', 'sql & postgres'): qidiruv so'rovi.
  • Moslik operatori: @@.
  • Natijalarni relevatlik bo'yicha saralash: ts_rank().
PostgreSQL / psql 
-- Matn ichidan qidirish
SELECT sarlavha
FROM maqolalar
WHERE to_tsvector('english', sarlavha || ' ' || matn) @@ to_tsquery('english', 'database & speed');
🐘 PostgreSQL 16 Server Natijasi:
⚡ PostgreSQL ning Full-Text qidiruvi ko'plab o'rta va yirik loyihalarda alohida ElasticSearch serverini saqlash xarajatlarini tejaydi.

Funksiyalar PostgreSQL Mavzu #21

PL/pgSQL — Maxsus Funksiyalar va Protseduralar

PostgreSQL o'zining ichki dasturlash tili bo'lgan PL/pgSQL ga ega. Unda o'zgaruvchilar, shartlar, sikllar va xatolarni qayta ishlash imkoniyatlari mavjud.

  • Yaratish: CREATE OR REPLACE FUNCTION funksiya_nomi(...) RETURNS tur AS $$ ... $$ LANGUAGE plpgsql;.
  • Biznes mantiqni to'g'ridan-to'g'ri ma'lumotlar bazasining ichida bajaradi (tarmoq kechikishini nolga tushiradi).
PostgreSQL / psql 
CREATE OR REPLACE FUNCTION qoshilgan_soliq(narx NUMERIC)
RETURNS NUMERIC AS $$
BEGIN
    RETURN narx * 1.12; -- 12% QQS hisoblash
END;
$$ LANGUAGE plpgsql;

-- Chaqirish:
SELECT qoshilgan_soliq(100000);
🐘 PostgreSQL 16 Server Natijasi:
💡 Serverda bajariluvchi funksiyalar yirik bank va to'lov tizimlarida xavfsizlik va tezlikni kafolatlaydi.

Trigger PostgreSQL Mavzu #22

Triggerlar — Hodisalarga Avtomatik Reaksiya

Trigger — jadvalda biror INSERT, UPDATE yoki DELETE amali bajarilganda avtomatik ishga tushuvchi maxsus mexanizmdir. U audit jurnallari yuritish va avtomatik hisob-kitoblar uchun qo'llaniladi.

  • Vaqti: BEFORE (amaldan oldin) yoki AFTER (amaldan so'ng).
  • Yangi va eski ma'lumotlar: NEW va OLD o'zgaruvchilarida saqlanadi.
PostgreSQL / psql 
-- Oxirgi o'zgartirilgan vaqtni avtomatik yangilovchi trigger funksiyasi
CREATE OR REPLACE FUNCTION yangilash_vaqti()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_mijoz_yangilandi
BEFORE UPDATE ON mijozlar
FOR EACH ROW
EXECUTE FUNCTION yangilash_vaqti();
🐘 PostgreSQL 16 Server Natijasi:
⚡ Triggerlar dasturchi unutib qoldirishi mumkin bo'lgan o'zgarish vaqti yoki audit jurnallarini 100% kafolatlaydi.

Views PostgreSQL Mavzu #23

Views va Materialized Views (Keshlanuvchi Ko'rinish)

PostgreSQL oddiy dinamik VIEW lardan tashqari og'ir so'rovlar natijasini qattiq diskda keshlab saqlab turuvchi Materialized View larni ham qo'llab-quvvatlaydi.

  • Oddiy VIEW: Har chaqirilganda so'rov qayta ishlaydi.
  • Materialized View: Og'ir analitik so'rov natijasi jismoniy saqlanadi va chaqirilganda 0.001 soniyada javob beradi.
  • Yangilash buyrug'i: REFRESH MATERIALIZED VIEW v_nomi;.
PostgreSQL / psql 
CREATE MATERIALIZED VIEW v_oylik_tushum AS
SELECT 
    DATE_TRUNC('month', created_at) AS oy,
    COUNT(*) AS buyurtmalar_soni,
    SUM(summa) AS jami_tushum
FROM buyurtmalar
GROUP BY 1;

-- Yangilash:
REFRESH MATERIALIZED VIEW v_oylik_tushum;
🐘 PostgreSQL 16 Server Natijasi:
🚀 Materialized View katta boshqaruv panellari (Dashboard) va grafiklar uchun eng tezkor yechimdir.

Xavfsizlik PostgreSQL Mavzu #24

PostgreSQL Tranzaksiyalari va Izolyatsiya Darajalari

PostgreSQL ACID tamoyillarini eng qat'iy standartlar asosida ta'minlaydi. U parallel so'rovlar bir-birining ma'lumotlarini buzib qo'ymasligi uchun MVCC (Multi-Version Concurrency Control) arxitekturasidan foydalanadi.

  • O'qish vaqtida bloklash bo'lmaydi: 'O'quvchilar yozuvchilarga, yozuvchilar esa o'quvchilarga xalaqit bermaydi'.
  • Izolyatsiya darajalari: Read Committed (standart), Repeatable Read, Serializable (eng qat'iy himoya).
  • Qatorlarni vaqtincha qulflash: SELECT ... FOR UPDATE;.
PostgreSQL / psql 
BEGIN;

-- Boshqa hech kim bu qatorni ayni paytda o'zgartira olmasligi uchun qulflash
SELECT balans FROM hisoblar WHERE id = 1 FOR UPDATE;

UPDATE hisoblar SET balans = balans - 50000 WHERE id = 1;

COMMIT;
🐘 PostgreSQL 16 Server Natijasi:
🔒 SELECT FOR UPDATE bank tizimlarida bir vaqtning o'zida ikkita joydan pul yechish (Race condition) muammosini butunlay yo'q qiladi.

Klaster PostgreSQL Mavzu #25

Replikatsiya — Streaming va Logical Replication

PostgreSQL ma'lumotlarni asosiy serverdan zaxira serverlarga real vaqt rejimida nusxalash uchun ikkita kuchli usulni taqdim etadi.

  • Streaming Replication (Fizik): WAL (Write-Ahead Log) baytlarini to'g'ridan-to'g'ri ikkilamchi serverga uzatadi. O'qish yuklamasini (Read Replica) taqsimlash uchun ayni muddao.
  • Logical Replication (Mantiqiy): Alohida jadvallarni tanlab boshqa turli xil versiyadagi Postgres bazalariga yuborish imkonini beradi (Publish/Subscribe).
PostgreSQL / psql 
# Standby server sozlamasi (postgresql.conf)
# primary_conninfo = 'host=192.168.1.10 port=5432 user=replicator'

-- Replikatsiya holatini tekshirish
SELECT client_addr, state, sync_state FROM pg_stat_replication;

💡 O'qish ko'p bo'lgan loyihalarda bir nechta Read Replica serverlar qo'yilib, foydalanuvchilar ularga taqsimlanadi.

Arxitektura PostgreSQL Mavzu #26

Table Partitioning — Katta Jadvallarni Bo'lish

Jadvalda 100 millionlab qatorlar to'planganda uni oylarga yoki yillarga qarab kichik mustaqil qismlarga (Partition) bo'lish usuli. So'rov yuborilganda Postgres faqat kerakli bo'lakni o'qiydi (Partition Pruning).

  • Bo'lish turlari: PARTITION BY RANGE (sanalar bo'yicha), LIST (davlatlar bo'yicha), HASH.
  • Foydalanuvchi bitta asosiy jadvalga murojaat qiladi, Postgres esa o'zi qatorlarni tegishli bo'lakka joylaydi.
PostgreSQL / psql 
CREATE TABLE loglar (
    id BIGSERIAL,
    xabar TEXT,
    created_at DATE NOT NULL
) PARTITION BY RANGE (created_at);

-- 2026-yil yanvar oyi uchun bo'lak
CREATE TABLE loglar_2026_01 PARTITION OF loglar
FOR VALUES FROM ('2026-01-01') TO ('2026-02-01');
🐘 PostgreSQL 16 Server Natijasi:
🚀 Partitioning orqali eski oylarning ma'lumotlarini o'chirish DROP TABLE loglar_2024_01 buyrug'i bilan bir zumda amalga oshadi.

Optimizatsiya PostgreSQL Mavzu #27

Performance Tuning — EXPLAIN ANALYZE va Xotira Sozlamalari

PostgreSQL so'rovlarini tahlil qilish va serverni apparat imkoniyatlariga to'liq moslashtirish dasturchilar va DBAlarning muhim vazifasidir.

  • EXPLAIN ANALYZE so'rov; — so'rovning har bir bosqichida qancha vaqt va xotira ketganini real ko'rsatadi.
  • Asosiy sozlamalar (postgresql.conf):
  • shared_buffers: RAM ning 25% qismi umumiy kesh uchun ajratiladi.
  • work_mem: Murakkab saralash va JOIN lar uchun har bir oqimga beriladigan tezkor xotira.
  • effective_cache_size: Operatsion tizim keshini hisobga oluvchi ko'rsatkich (RAM ning 50-75% i).
PostgreSQL / psql 
EXPLAIN ANALYZE
SELECT ism, email FROM mijozlar WHERE email = 'akmal@uz';
🐘 PostgreSQL 16 Server Natijasi:
⚡ Execution Time: 0.035 ms — to'g'ri sozlangan indeks va parametrlar orqali so'rovlar sekundning o'n mingdan bir ulushida bajariladi.

Admin PostgreSQL Mavzu #28

Backup va Restore — pg_dump va pg_restore

Ma'lumotlar bazasining zaxira nusxasini olish (Backup) va falokat ro'y berganda uni qayta tiklash (Restore) usullari.

  • Zaxira olish (SQL matn ko'rinishida): pg_dump -U postgres w3learn > backup.sql.
  • Maxsus siqilgan formatda (Custom format - tavsiya etiladi): pg_dump -U postgres -Fc w3learn > backup.dump.
  • Qayta tiklash: pg_restore -U postgres -d yangi_baza -v backup.dump.
  • Barcha bazalar va foydalanuvchilarning zaxirasi: pg_dumpall > all.sql.
PostgreSQL / psql 
# Terminalda zaxira nusxa olish:
pg_dump -U postgres -Fc -b -v -f w3learn_20261123.dump w3learn

# Yangi serverda qayta tiklash:
pg_restore -U postgres -d w3learn_yangi -v w3learn_20261123.dump
🐘 PostgreSQL 16 Server Natijasi:
🔒 Har qanday jiddiy loyihada kunlik avtomatik backup skriptlari (cron job) sozlanishi va fayllar alohida bulutga (S3) yuklanishi shart.
