Asosiy Git Mavzu #1

Git Nima? Versiyalarni Boshqarish Tizimi (VCS)

Git — Linux yadrosi asoschisi Linus Torvalds tomonidan 2005-yilda yaratilgan, dunyodagi eng mashhur taqsimlangan versiyalarni boshqarish tizimidir (Distributed Version Control System). U loyiha kodi ustida kiritilgan har bir o'zgarish tarixini saqlaydi va bir vaqtning o'zida yuzlab dasturchilarning birgalikda ishlashiga imkon beradi.

  • Taqsimlangan (Distributed): Har bir dasturchining kompyuterida loyihaning to'liq tarixi mavjud bo'ladi.
  • Xavfsizlik: Barcha fayllar va kommitlar SHA-1 / SHA-256 xesh kriptografiyasi orqali himoyalangan.
  • Tezlik: Deyarli barcha amallar (tarixni ko'rish, diff solishtirish, tarmoqlash) internetga ulanmasdan mahalliy diskda bajariladi.
  • GitHub, GitLab, Bitbucket kabi global servislar Git poydevorida ishlaydi.
Git Bash / Terminal 
# Git o'rnatilganligini va versiyasini tekshirish
git --version
💻 Git Console Natijasi:
💡 Git va GitHub boshqa-boshqa narsalar: Git bu dastur (VCS), GitHub esa Git repozitoriylarini bulutda saqlovchi va hamkorlikni ta'minlovchi veb-platformadir.

O'rnatish Git Mavzu #2

Git O'rnatish va Muhitni Tayyorlash

Git deyarli barcha operatsion tizimlarda ishlaydi. O'rnatishdan so'ng terminal orqali boshqarish eng qulay usuldir.

  • Windows: git-scm.com saytidan 'Git for Windows' yuklab olinadi (u bilan birga qulay Git Bash terminali keladi).
  • macOS: Terminalda git --version yozilsa, avtomatik ravishda Xcode Command Line Tools o'rnatiladi yoki brew install git.
  • Linux (Ubuntu/Debian): sudo apt update && sudo apt install git -y.
Git Bash / Terminal 
# Linux tizimlarida o'rnatish
sudo apt update
sudo apt install git -y

# O'rnatishni tekshirish
git --version
💻 Git Console Natijasi:
💡 Windows foydalanuvchilariga doimo 'Git Bash' terminali orqali ishlash tavsiya etiladi, chunki u Linux buyruqlarini ham to'liq quvvatlaydi.

Sozlash Git Mavzu #3

Git Config: Dasturchi Ismi va Emaili

Git da birinchi marta ishlashdan oldin kim kod yozayotganini aniqlash uchun ism va elektron pochtani global tarzda kiritish shart. Ushbu ma'lumotlar har bir kommitga muhrlanadi.

  • git config --global user.name "Ismingiz" — muallif ismini belgilash.
  • git config --global user.email "emailingiz@example.com" — muallif emailini kiritish (GitHub dagi email bilan bir xil bo'lishi maqsadga muvofiq).
  • git config --list — joriy barcha sozlamalarni ko'rish.
Git Bash / Terminal 
# Global foydalanuvchi ma'lumotlarini kiritish
git config --global user.name "Alisher Navoiy"
git config --global user.email "alisher@example.uz"

# Asosiy tarmoq nomini "main" deb belgilash
git config --global init.defaultBranch main

# Sozlamalarni tekshirish
git config user.name
git config user.email
💻 Git Console Natijasi:
💡 --global bayrog'i sozlamani butun kompyuterdagi barcha repozitoriylar uchun amal qiladigan qilib sozlaydi.

Asosiy Git Mavzu #4

git init: Yangi Repozitoriy Yaratish

Mavjud bo'lgan istalgan papkani Git repozitoriyasiga aylantirish uchun git init buyrug'i ishlatiladi. Bu joriy papkada yashirin .git katalogini yaratadi.

  • .git papkasi loyihaning barcha tarixi, tarmoqlari va kommitlarini o'zida saqlaydi.
  • Agar .git papkasi o'chirib tashlansa, loyiha oddiy papkaga aylanadi va versiyalar tarixi yo'qoladi.
  • Faqat loyiha ildiz (root) papkasida bir marta ishga tushiriladi.
Git Bash / Terminal 
# Yangi papka ochib, uni Git loyihasiga aylantirish
mkdir mening-saytim
cd mening-saytim
git init

💡 Endi ushbu papkadagi har qanday o'zgarishlar Git nazorati ostiga olinadi.

Holat Git Mavzu #5

git status: Fayllar Holatini Tekshirish

git status — Git dagi eng muhim va eng ko'p ishlatiladigan buyruq. U qaysi fayllar o'zgargani, qaysilari kutish maydoniga (staging area) qo'shilgani yoki nazorat qilinmayotganini (untracked) ko'rsatadi.

  • Untracked files (Qizil): Yangi yaratilgan, hali Git ga qo'shilmagan fayllar.
  • Changes not staged (Qizil): Tahrirlangan, lekin hali git add qilinmagan fayllar.
  • Changes to be committed (Yashil): git add qilingan, kommitga tayyor kutish maydonidagi fayllar.
Git Bash / Terminal 
# Yangi fayl yaratib, statusni ko'rish
echo "<h1>Salom Dunyo</h1>" > index.html
git status
💻 Git Console Natijasi:
💡 Har qanday harakatdan oldin va keyin `git status` yozib turish xatolarning oldini oladi.

Asosiy Git Mavzu #6

git add: Staging Area (Kutish Maydoni)

Git da o'zgarishlarni to'g'ridan-to'g'ri kommit qilib bo'lmaydi. Avval qaysi fayllarni kommitga kiritmoqchi ekanligingizni Staging Area (indeks) ga qo'shishingiz kerak.

  • git add fayl_nomi.js — faqat ko'rsatilgan aniq faylni qo'shish.
  • git add . yoki git add -A — joriy papkadagi barcha yangi va o'zgartirilgan fayllarni qo'shish.
  • git restore --staged fayl_nomi — xato qo'shilgan faylni staging areadan qaytarib chiqarish.
Git Bash / Terminal 
# index.html faylini staging areaga qo'shamiz
git add index.html
git status
💻 Git Console Natijasi:
💡 Staging Area yordamida siz bir nechta fayllardan faqat keraklilarini tanlab-tanlab alohida mantiqiy kommitlarga ajratishingiz mumkin.

Kommit Git Mavzu #7

git commit: O'zgarishlarni Tarixga Muhrlash

git commit — staging areadagi barcha o'zgarishlarni loyihaning o'chmas tarixiga (snapshot) saqlaydi. Har bir kommit aniq xabar (commit message) bilan yozilishi shart.

  • git commit -m "Xabar matni" — qisqa tushunarli izoh bilan kommit qilish.
  • Kommit xabari qoidasi: nima qilinganini aniq va lo'nda yozish (masalan: 'feat: add login modal', 'fix: responsive navbar').
  • Har bir kommit o'zining noyob SHA-1 xesh identifikatoriga ega bo'ladi (masalan: a1b2c3d).
Git Bash / Terminal 
# Kommit qilish
git commit -m "feat: birinchi index.html sahifasi yaratildi"
git status
💻 Git Console Natijasi:
💡 `working tree clean` degani barcha o'zgarishlar muvaffaqiyatli saqlanganini bildiradi.

Tarix Git Mavzu #8

git log: Kommitlar Tarixi

Loyihada kim, qachon va qanday o'zgarishlar kiritganini ko'rish uchun git log buyrug'idan foydalaniladi.

  • git log — to'liq ma'lumot (muallif, sana, to'liq xesh, xabar).
  • git log --oneline — har bir kommitni bitta ixcham qatorda ko'rsatish.
  • git log -n 5 — faqat oxirgi 5 ta kommitni chiqarish.
  • git log --graph --oneline --all — tarmoqlar va birlashishlarni chiroyli grafik daraxt ko'rinishida ko'rsatish.
Git Bash / Terminal 
# Kommitlar tarixini ixcham ko'rish
git log --oneline
💻 Git Console Natijasi:
💡 Q orqali git log sahifasidan chiqib terminalga qaytishingiz mumkin.

Tahlil Git Mavzu #9

git diff: O'zgarishlarni Satrma-Satr Solishtirish

Fayllarga kiritilgan har bir belgi va satr farqini ko'rish uchun git diff ishlatiladi.

  • git diff — ishchi maydon va staging area o'rtasidagi farqni ko'rsatadi.
  • git diff --staged — staging area va oxirgi kommit o'rtasidagi farqni solishtiradi.
  • + (yashil) — yangi qo'shilgan satrlar.
  • - (qizil) — o'chirilgan yoki almashtirilgan eski satrlar.
Git Bash / Terminal 
# Faylga o'zgartirish kiritib, diff ko'rish
echo "<p>Yangi matn</p>" >> index.html
git diff
💻 Git Console Natijasi:
💡 Kommit qilishdan oldin doim git diff qilib, adashib ortiqcha console.log yoki parollarni qo'shib yubormaganligingizga ishonch hosil qiling.

Tarmoqlar Git Mavzu #10

git branch: Tarmoqlanish (Branches)

Tarmoq (branch) — asosiy kodga (main) teginmasdan, alohida mustaqil parallel muhitda yangi funksiyalar (features) yaratish yoki xatolarni to'g'rilash (bugfix) imkoniyatidir.

  • git branch — mavjud barcha mahalliy tarmoqlarni ko'rsatadi (* belgisi joriy tarmoqni bildiradi).
  • git branch yangi-funksiya — yangi tarmoq ochish.
  • git branch -d tarmoq-nomi — keraksiz tarmoqni xavfsiz o'chirish.
  • Tarmoqlash Git da bir zumda (O(1)) ro'y beradi, chunki tarmoq shunchaki oxirgi kommitga ishora qiluvchi yengil ko'rsatkichdir.
Git Bash / Terminal 
# Yangi tarmoq ochish va ro'yxatni ko'rish
git branch feature-login
git branch
💻 Git Console Natijasi:
💡 Asosiy barqaror kod doimo main (yoki master) tarmog'ida saqlanadi, har bir yangi vazifa uchun yangi branch ochiladi.

Tarmoqlar Git Mavzu #11

git checkout va switch: Tarmoqlararo O'tish

Boshqa tarmoqqa o'tish yoki yangi tarmoq ochib unga darhol sakrash buyruqlari.

  • git checkout tarmoq-nomi — an'anaviy o'tish buyrug'i.
  • git switch tarmoq-nomi — yangi zamonaviy va xavfsiz o'tish buyrug'i (Git 2.23+).
  • git checkout -b yangi-tarmoq — bitta qadamda ham yangi tarmoq ochish, ham unga o'tish.
  • git switch -c yangi-tarmoq — zamonaviy ko'rinishi (-c = create).
Git Bash / Terminal 
# Yangi tarmoq ochib, unga birdaniga o'tamiz
git switch -c feature-navbar
git branch
💻 Git Console Natijasi:
💡 Yangi tarmoqqa o'tganingizdan so'ng qilingan barcha kommitlar faqat ushbu tarmoqqa tegishli bo'ladi.

Birlashtirish Git Mavzu #12

git merge: Tarmoqlarni Birlashtirish

Yangi funksiya (feature) tayyor bo'lgach, uni asosiy tarmoqqa (main) qo'shish uchun git merge buyrug'i ishlatiladi.

  • 1. Avval qabul qiluvchi tarmoqqa o'tiladi: git switch main.
  • 2. Birlashtirish buyrug'i beriladi: git merge feature-navbar.
  • Fast-forward merge: Agar asosiy tarmoqda boshqa kommitlar bo'lmagan bo'lsa, ko'rsatkich to'g'ridan-to'g'ri oldinga siljiydi.
  • 3-way merge: Agar ikkala tarmoqda ham o'zgarishlar bo'lsa, yangi umumiy birlashtiruvchi kommit (merge commit) yasaladi.
Git Bash / Terminal 
# main tarmog'iga o'tib, feature ni birlashtirish
git switch main
git merge feature-navbar
💻 Git Console Natijasi:
💡 Agar bir xil faylning bir xil satri ikkala tarmoqda turlicha o'zgartirilgan bo'lsa, 'Merge Conflict' yuzaga keladi va uni qo'lda hal qilish lozim bo'ladi.

Ilg'or Git Mavzu #13

git rebase: Tarixni Toza va Tekis Saqlash

Rebase — joriy tarmoqning boshlang'ich nuqtasini boshqa tarmoqning eng so'nggi kommitiga ko'chirish amali. Natijada kommitlar tarixi chigal tarmoqlarsiz, bitta to'g'ri chiziqdek tekis ko'rinadi.

  • Merge dan farqi: Merge qo'shimcha 'Merge branch ...' kommiti yasaydi, Rebase esa kommitlarni birin-ketin qayta yozadi.
  • git rebase main — main dagi eng yangi o'zgarishlarni o'z tarmog'ingiz ostiga poydevor qilib olish.
  • Qoida: Public (ommaviy ulashilgan) tarmoqlarda hech qachon rebase qilmang!
Git Bash / Terminal 
# Feature tarmog'ida turib main ustiga rebase qilish
git switch feature-payment
git rebase main
💻 Git Console Natijasi:
💡 Rebase loyiha tarixini chiroyli va o'qishga oson qiladi, lekin ommaviy kommitlarning xeshlarini o'zgartirishi sababli ehtiyotkorlikni talab qiladi.

Foydali Git Mavzu #14

git stash: Chala Ishlarni Vaqtincha Saqlash

Agar siz kod yozayotgan bo'lsangiz-u, ish hali tugamagan bo'lsa (kommit qilishga erta), lekin shoshilinch boshqa tarmoqqa o'tish kerak bo'lib qolsa, git stash yordamga keladi.

  • git stash — chala o'zgarishlarni maxsus vaqtinchalik javonga olib qo'yadi va ishchi katalogingizni tozalaydi.
  • git stash pop — saqlangan oxirgi o'zgarishlarni qaytarib olib keladi va javondan o'chiradi.
  • git stash list — javonda saqlanayotgan barcha chala ishlarni ko'rsatadi.
  • git stash drop — keraksiz stashni o'chirish.
Git Bash / Terminal 
# Ishlarni vaqtincha olib qo'yish
git stash save "header tahrirlari chala qoldi"

# Shoshilinch xatoni tuzatib kelgach, qaytarib olish:
git stash pop
💻 Git Console Natijasi:
💡 git stash hech qanday kommit yaratmasdan tarmoqlararo erkin harakatlanish imkonini beradi.

Masofaviy Git Mavzu #15

git remote: Masofaviy Serverlar bilan Bog'lanish

Mahalliy (kompyuteringizdagi) Git loyihasini GitHub, GitLab yoki Bitbucket kabi bulutli serverlar bilan bog'lash uchun git remote ishlatiladi.

  • git remote -v — ulangan masofaviy manzillarni ko'rish.
  • git remote add origin https://github.com/user/repo.git — loyihani yangi masofaviy serverga bog'lash (standart nomi 'origin').
  • git remote remove origin — bog'lanishni uzish.
Git Bash / Terminal 
# GitHub repozitoriyasini bog'lash va tekshirish
git remote add origin https://github.com/avdurasulovuz/w3learn.git
git remote -v
💻 Git Console Natijasi:
💡 'origin' — bu shunchaki masofaviy server URL manziliga berilgan qulay taxallus (alias) dir.

Masofaviy Git Mavzu #16

git clone: Repozitoriyni Ko'chirib Olish

Internetdagi (GitHub, GitLab) mavjud ochiq yoki yopiq loyihaning butun fayllari va to'liq kommitlar tarixini kompyuteringizga bir zumda yuklab olish buyrug'i.

  • git clone — yangi papka ochib, butun loyihani yuklaydi.
  • Clone qilingan loyihada git init qilish shart emas, chunki u allaqachon tayyor Git repozitoriyasi hisoblanadi va 'origin' avtomatik ulangan bo'ladi.
Git Bash / Terminal 
# Ochiq kodli loyihani kompyuterga yuklab olish

Masofaviy Git Mavzu #17

git push: Kodlarni Serverga Yuklash

Kompyuteringizda qilingan yangi mahalliy kommitlarni masofaviy GitHub/GitLab serveriga yuborish.

  • git push -u origin main — birinchi marta asosiy tarmoqqa yuklash (-u kelgusida faqat 'git push' yozish imkonini beradi).
  • git push origin feature-name — yangi tarmoqni GitHub ga yuklash.
  • Agar serverda sizda yo'q boshqa yangi kommitlar bo'lsa, Git push ni rad etadi va avval pull qilishni so'raydi.
Git Bash / Terminal 
# Kommitlarni GitHub ga yuklash
git push origin main
💻 Git Console Natijasi:

Masofaviy Git Mavzu #18

git pull: Yangilanishlarni Yuklab Olish

Jamoangizdagi boshqa dasturchilar GitHub ga yuklagan yangi kommitlarni o'z kompyuteringizga olib kelib, joriy kodingiz bilan birlashtirish.

  • git pull origin main — masofaviy o'zgarishlarni yuklab, joriy tarmoqqa merge qiladi.
  • Aslida git pull = git fetch + git merge ning bitta buyruqdagi ifodasidir.
  • Jamoada ishlayotganda har kuni ertalab kod yozishdan oldin git pull qilish oltin qoidadir.
Git Bash / Terminal 
# GitHub dan yangi kodlarni tortib olish
git pull origin main
💻 Git Console Natijasi:
💡 Har doim yangi o'zgarish kiritishdan avval pull qilib tursangiz, konfliktlar ehtimoli kamayadi.

Masofaviy Git Mavzu #19

git fetch: Xavfsiz Tekshirish

git fetch masofaviy serverdagi barcha yangi kommitlar va tarmoqlar ma'lumotlarini yuklab oladi, lekin ularni sizning mahalliy kodingiz bilan avtomatik birlashtirmaydi.

  • Pull dan farqli ravishda, fetch hech qachon sizning kodingizni buzmaydi yoki merge qilmaydi.
  • Serverda nima yangiliklar borligini xavfsiz ko'rish uchun git fetch qilib, keyin git log origin/main bilan tekshirish mumkin.
Git Bash / Terminal 
# Masofaviy o'zgarishlarni xavfsiz tekshirish
git fetch origin
git status
💻 Git Console Natijasi:
💡 Fetch orqali siz kodingiz serverdan necha kommit orqada yoki oldinda ekanligini bilib olasiz.

Hamkorlik Git Mavzu #20

Fork va Pull Request (PR): Ochiq Kodli Loyihalar

O'zgalarning ochiq kodli (Open Source) loyihalariga hissa qo'shish (contribute qilish) mexanizmi.

  • Fork: Birovning GitHub dagi repozitoriyasidan o'zingizning shaxsiy akkauntingizga to'liq nusxa ko'chirib olish (GitHub dagi maxsus tugma).
  • O'z forkingizda yangi tarmoq ochib, xatoni tuzatasiz yoki yangi imkoniyat qo'shasiz.
  • Pull Request (PR): Asl loyiha egalariga 'Mening mana bu tuzatishlarimni asosiy loyihangizga qo'shib olishingizni so'rayman' deb taklif yuborish.
Git Bash / Terminal 
# Fork qilingan loyihani klonlab, hissa qo'shish
git clone https://github.com/mening-akkauntim/mashhur-loyiha.git
cd mashhur-loyiha
git switch -c fix-uzbek-typo
# ... o'zgarishlar kiritiladi ...
git commit -am "fix: o'zbekcha tarjimadagi xato tuzatildi"
git push origin fix-uzbek-typo
💻 Git Console Natijasi:
💡 Pull Request orqali kod tekshiriladi (Code Review) va ma'qullansa, bitta tugma bilan asosiy loyihaga birlashtiriladi.

Xavfsizlik Git Mavzu #21

.gitignore: Keraksiz Fayllarni Istisno Qilish

Loyiha papkasidagi ba'zi fayllarni (parollar, maxfiy kalitlar, node_modules, build fayllar) hech qachon Git tarixiga yoki GitHub ga yuklamaslik kerak. Buning uchun loyiha ildizida .gitignore fayli yaratiladi.

  • Har bir satrda bitta qoida yoziladi.
  • node_modules/ — butun papkani e'tiborsiz qoldirish.
  • .env — maxfiy kalitlar va tokenlar faylini yashirish.
  • *.log — barcha log fayllarni istisno qilish.
  • dist/ yoki build/ — kompilyatsiya qilingan fayllarni chetlab o'tish.
Git Bash / Terminal 
# Standart .gitignore fayli namunasi:
# Bog'liqliklar
node_modules/
vendor/

# Maxfiy ma'lumotlar
.env
.env.local
id_rsa

# Tizim fayllari
.DS_Store
Thumbs.db

# Loglar
*.log
npm-debug.log*
💻 Git Console Natijasi:
⚠️ Hech qachon `.env` faylini Git ga kommit qilmang! Parollaringiz ochiq internetga chiqib ketishi mumkin.

Versiyalash Git Mavzu #22

git tag: Relizlar va Versiyalarni Belgilash

Dasturning rasmiy barqaror versiyalarini (masalan: v1.0.0, v2.1.0) tarixda muhrlab qo'yish uchun teglar ishlatiladi.

  • git tag -a v1.0.0 -m "Reliz 1.0.0 barqaror versiya" — izohli teg yaratish.
  • git tag — barcha teglarni ro'yxat qilish.
  • git push origin --tags — barcha teglarni GitHub ga yuklash (GitHub da avtomatik ravishda 'Releases' bo'limi paydo bo'ladi).
Git Bash / Terminal 
# 1.0.0 versiya tegi yaratish
git tag -a v1.0.0 -m "Birinchi rasmiy reliz"

Bekor qilish Git Mavzu #23

git reset: O'zgarishlarni Bekor Qilish

Noto'g'ri qilingan kommitlarni yoki staging areadagi fayllarni orqaga qaytarish uchun git reset ishlatiladi.

  • git reset --soft HEAD~1 — oxirgi kommitni bekor qiladi, lekin fayllardagi o'zgarishlar staging areada (yashil) saqlanib qoladi.
  • git reset --mixed HEAD~1 (standart) — kommitni bekor qiladi, fayllarni ishchi maydonga qaytaradi (qizil).
  • git reset --hard HEAD~1 — ⚠️ XAVFLI: oxirgi kommitni ham, fayllardagi barcha o'zgarishlarni ham butunlay yo'q qiladi!
Git Bash / Terminal 
# Oxirgi kommitni yumshoq qaytarish (soft reset)
git reset --soft HEAD~1
git status

💡 Hard reset qilishdan oldin o'zgarishlaringiz butunlay o'chib ketishidan ogoh bo'ling!

git revert: Xavfsiz Bekor Qilish Kommiti

Agar xato kommit allaqachon GitHub ga yuklab bo'lingan bo'lsa, reset o'rniga git revert ishlatiladi.

  • Tarix o'chirilmaydi va buzilmaydi, faqat teskari o'zgarish bilan yangi kommit qo'shiladi.

Arxitektura Git Mavzu #25

GitFlow va Trunk-Based Ishlash Modellari

Katta dasturchilar jamoalarida tarmoqlardan qanday foydalanish bo'yicha standart kelishuvlar mavjud.

  • GitFlow: main (production relizlar), develop (ishlanayotgan umumiy kod), feature/* (yangi funksiyalar), release/* (relizga tayyorgarlik), hotfix/* (tezkor xatolarni tuzatish).
  • Trunk-Based Development: Kichik jamoalar uchun zamonaviy model. Hamma qisqa yashovchi kichik tarmoqlar orqali to'g'ridan-to'g'ri main ga tez-tez (har kuni) merge qiladi.
  • Zamonaviy DevOps va CI/CD muhitlarida Trunk-Based usuli ko'proq afzal ko'rilmoqda.
Git Bash / Terminal 
# GitFlow uslubida yangi funksiya ochish:
git switch develop
git switch -c feature/sms-integration

# Tugatgach:
git switch develop
git merge --no-ff feature/sms-integration
git branch -d feature/sms-integration

💡 Qaysi modelni tanlashingizdan qat'i nazar, jamoaning barcha a'zolari bir xil qoidalarga rioya qilishi lozim.

DevOps Git Mavzu #26

GitHub Actions va CI/CD Avtomatlashtirish

CI/CD (Uzluksiz integratsiya va yetkazib berish) — har safar yangi kod push qilinganda testlarni avtomatik ishga tushirish va dasturni serverga joylash jarayoni.

  • GitHub Actions konfiguratsiyasi .github/workflows/*.yml fayllarida saqlanadi.
  • Har bir kommitda avtomatik npm test yoki kod sifatini (linter) tekshirish.
  • Xatolar bo'lsa darhol bildirishnoma berish va xavfli kodning serverga chiqib ketishini to'xtatish.
Git Bash / Terminal 
# .github/workflows/test.yml fayli
name: Node.js CI

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4
    - name: Node.js o'rnatish
      uses: actions/setup-node@v4
      with:
        node-version: '20'
    - run: npm ci
    - run: npm test
💻 Git Console Natijasi:
💡 GitHub Actions dasturchilarga qo'lda test va deploy qilish vaqtini tejab, jarayonni to'liq avtomatlashtiradi.
