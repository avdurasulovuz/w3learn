Asosiy Redis Mavzu #1

Redis Nima? In-Memory Ma'lumotlar Tuzilmasi

Redis (Remote Dictionary Server) — operativ xotirada (RAM) ishlovchi, favqulodda yuqori tezlikka ega ochiq kodli ma'lumotlar ombori. U ma'lumotlar bazasi, kesh (cache) va xabarlar brokering (message broker) sifatida dunyoning deyarli barcha yirik loyihalarida qo'llaniladi.

  • Operativ xotirada ishlaganligi sababli so'rovlarni mikrosekundlarda bajaradi (100,000+ RPS).
  • Oddiy kalit-qiymat (Key-Value) dan tashqari boy ma'lumotlar tuzilmalarini (Lists, Hashes, Sets, Sorted Sets) qo'llab-quvvatlaydi.
  • Twitter, GitHub, Uber, Netflix kabi gigantlar kesh, sessiya va real-vaqt hisoblagichlari uchun Redis dan foydalanadi.
  • Doimiylik: Xotirada ishlasa-da, ma'lumotlarni diskka (RDB va AOF) nusxalab xavfsiz saqlay oladi.
Redis CLI / Commands 
# redis-server holatini tekshirish
redis-cli ping

# Ma'lumot yozish va o'qish
SET salom "Salom, O'zbekiston!"
GET salom
⚡ Redis In-Memory CLI Natijasi:
💡 Redis operativ xotirada ishlagani sababli diskka nisbatan yuzlab marta tezroq ishlaydi.

O'rnatish Redis Mavzu #2

Redis O'rnatish va Ishga Tushirish

Redis Linux muhitida eng qulay ishlaydi. Windows tizimida esa WSL 2 (Windows Subsystem for Linux) yoki Docker orqali o'rnatish tavsiya etiladi.

  • Linux/Ubuntu: sudo apt install redis-server.
  • Standart port: 6379.
  • Xizmatni tekshirish: sudo systemctl status redis.
  • Docker orqali tezda ishga tushirish: docker run -d -p 6379:6379 --name my-redis redis.
Redis CLI / Commands 
# Ubuntu/Debian tizimida o'rnatish
sudo apt update
sudo apt install redis-server -y

# Xizmatni yoqish
sudo systemctl enable redis-server
sudo systemctl start redis-server
⚡ Redis In-Memory CLI Natijasi:
💡 Windows foydalanuvchilari uchun WSL (Ubuntu) yoki Docker Desktop orqali o'rnatish rasmiy tavsiya hisoblanadi.

CLI Redis Mavzu #3

Redis-CLI Asosiy Buyruqlari

redis-cli — Redis serveriga buyruqlar yuborish va natijalarni ko'rish uchun mo'ljallangan qulay konsol interfeysi.

  • redis-cli — mahalliy serverga (127.0.0.1:6379) ulanish.
  • PING — server tirikligini tekshirish (javob: PONG).
  • KEYS * — bazadagi barcha kalitlarni ko'rish (ehtiyot bo'ling, productionda KEYS o'rniga SCAN tavsiya etiladi).
  • DBSIZE — joriy bazadagi kalitlar sonini hisoblash.
  • FLUSHALL — barcha bazalardagi barcha kalitlarni tozalash.
Redis CLI / Commands 
# redis-cli ga ulanish va buyruqlar
redis-cli
127.0.0.1:6379> PING
127.0.0.1:6379> DBSIZE
127.0.0.1:6379> KEYS *
127.0.0.1:6379> INFO memory
⚡ Redis In-Memory CLI Natijasi:
⚠️ Katta hajmli production bazalarda hech qachon KEYS * buyrug'ini ishlatmang, chunki u serverni bloklab qo'yishi mumkin. Buning o'rniga SCAN buyrug'idan foydalaning.

Arxitektura Redis Mavzu #4

Redis Ma'lumot Turlari (Data Types)

Redis oddiy kalit-qiymat bazasi emas — u ma'lumotlar tuzilmasi serveridir. Unda quyidagi 5 ta asosiy ma'lumot turi mavjud.

  • String: Oddiy matn, raqam yoki ikkilik ma'lumot (maksimal 512 MB).
  • List: Qo'shaloq bog'langan ro'yxat (navbat va stek uchun).
  • Hash: Ob'ekt maydonlari va qiymatlari (masalan, foydalanuvchi profili).
  • Set: Takrorlanmas elementlarning tartiblanmagan to'plami.
  • Sorted Set (ZSet): Har bir elementga ball (score) biriktirilgan va tartiblangan to'plam.
Redis CLI / Commands 
# Kalitning turini tekshirish: TYPE buyrug'i
SET username "islombek"
TYPE username

LPUSH vazifalar "kod yozish"
TYPE vazifalar

HSET user:1 ism "Ali" yosh 25
TYPE user:1
⚡ Redis In-Memory CLI Natijasi:
💡 Har bir ma'lumot turi o'zining mos foydalanish holatiga ega: kesh uchun String, navbatlar uchun List, profillar uchun Hash, reytinglar uchun Sorted Set.

Strings Redis Mavzu #5

SET va GET Buyruqlari (Strings)

String — Redis dagi eng ko'p ishlatiladigan ma'lumot turidir. SET qiymatni saqlaydi, GET esa uni o'qib beradi.

  • SET key value — kalitga matn yoki raqam yozish.
  • GET key — kalit qiymatini olish.
  • SETNX key value — faqat kalit avval mavjud bo'lmaganda yozish (distribyutiv qulflash uchun).
  • APPEND key value — mavjud matn oxiriga qo'shimcha ulash.
Redis CLI / Commands 
# Stringlar bilan amallar
SET website "w3learn.uz"
GET website

# Mavjud bo'lmasa yozish (SETNX)
SETNX website "boshqa.uz"

# Oxiriga matn qo'shish
APPEND website "/courses"
GET website
⚡ Redis In-Memory CLI Natijasi:
💡 SETNX 0 qaytarsa, demak kalit allaqachon mavjud bo'lgan va yangilanmagan.

Kesh Redis Mavzu #6

EXPIRE va TTL: Amal Qilish Muddati

Redis kesh boshqaruvining yuragi TTL (Time To Live) hisoblanadi. Siz istalgan kalitga soniyalarda yashash muddatini belgilashingiz mumkin, muddat tugagach Redis uni avtomatik o'chiradi.

  • EXPIRE key seconds — kalitga yashash muddatini berish.
  • TTL key — kalitning qolgan soniyalarini tekshirish.
  • SETEX key seconds value — SET va EXPIRE ni bir qatorda bajarish.
  • TTL natijalari: ijobiy son (qolgan soniya), -1 (muddatsiz, abadiy), -2 (kalit topilmadi/o'chgan).
Redis CLI / Commands 
# Keshga 60 soniyalik SMS kodini saqlash
SETEX otp:998901234567 60 "849204"

# Qolgan muddatni ko'rish
TTL otp:998901234567

# Doimiy kalitga muddat berish
SET session:user101 "active"
EXPIRE session:user101 3600
TTL session:user101
⚡ Redis In-Memory CLI Natijasi:
💡 Kesh tizimlarida xotira to'lib qolmasligi uchun barcha kesh kalitlariga aniq TTL belgilash shart.

Hisoblagich Redis Mavzu #7

INCR va DECR: Atomik Sanagichlar

Redis raqamli qiymatlarni atomik tarzda (poyga holatlari - race condition siz) oshirish yoki kamaytirish imkonini beradi.

  • INCR key — qiymatni 1 ga oshiradi (agar kalit bo'lmasa, 0 dan 1 ga o'tadi).
  • DECR key — qiymatni 1 ga kamaytiradi.
  • INCRBY key increment — qiymatni ko'rsatilgan miqdorga oshiradi.
  • Sayt tashrifchilari, kliklar, like-lar va API rate limiter lar uchun ideal.
Redis CLI / Commands 
# Post ko'rishlar sonini sanash
INCR post:99:views
INCR post:99:views
INCRBY post:99:views 10

# Mahsulot qoldig'ini kamaytirish
SET ombor:tovar_15 50
DECR ombor:tovar_15
GET ombor:tovar_15
⚡ Redis In-Memory CLI Natijasi:
💡 INCR operatsiyasi bir vaqtning o'zida minglab so'rovlar kelsa ham adashmasdan to'g'ri hisoblaydi.

Strings Redis Mavzu #8

MSET va MGET: Guruhli Amallar

Bitta buyruq orqali bir nechta kalitlarni birdaniga yozish va o'qish tarmoq uzatish vaqtini (round-trip time) sezilarli darajada tejaydi.

  • MSET k1 v1 k2 v2 ... — bir nechta kalit-qiymatlarni saqlash.
  • MGET k1 k2 k3 ... — bir nechta kalitlarning qiymatlarini bitta massivda olish.
  • Agar kalitlardan biri topilmasa, uning o'rniga nil qaytadi.
  • Tarmoqdagi kechikishlarni kamaytirishning eng yaxshi usuli.
Redis CLI / Commands 
# Bir vaqtda bir nechta sozlamalarni saqlash
MSET app:name "W3Learn" app:version "2.5" app:env "production"

# Hammasini bir so'rovda olish
MGET app:name app:version app:env app:unknown
⚡ Redis In-Memory CLI Natijasi:
💡 Tarmoq orqali 10 ta alohida GET yuborgandan ko'ra bitta MGET yuborish 5-10 barobar tezroq ishlaydi.

Lists Redis Mavzu #9

LPUSH va RPUSH: Ro'yxatlar (Lists)

Redis List — bu simmetrik bog'langan ro'yxat bo'lib, uning boshiga yoki oxiriga element qo'shish O(1) doimiy vaqt oladi.

  • LPUSH key value... — ro'yxat boshiga (chap tomonga) elementlar qo'shish.
  • RPUSH key value... — ro'yxat oxiriga (o'ng tomonga) elementlar qo'shish.
  • Xabarlar navbati (Message Queue) va oxirgi harakatlar lentasi (Activity Feed) uchun xizmat qiladi.
Redis CLI / Commands 
# Vazifalar navbatiga yangi ishlar qo'shish
RPUSH queue:emails "user1@mail.uz" "user2@mail.uz"
LPUSH queue:emails "urgent_admin@mail.uz"

# Elementlar ro'yxatini ko'rish
LRANGE queue:emails 0 -1
⚡ Redis In-Memory CLI Natijasi:
💡 LPUSH ro'yxatning boshiga tiqadi, RPUSH esa oxiriga ulaydi.

Lists Redis Mavzu #10

LRANGE: Ro'yxat Elementlarini O'qish

LRANGE berilgan indeks oralig'idagi elementlarni ajratib oladi. Salbiy indekslar oxiridan sanaladi (-1 eng oxirgi element).

  • LRANGE key start stop — indekslar bo'yicha qirqib olish.
  • 0 -1 — ro'yxatdagi barcha elementlarni olish.
  • 0 9 — eng birinchi 10 ta elementni olish (paginatsiya uchun).
  • LTRIM key start stop — ro'yxatni qirqib, faqat belgilangan oraliqni qoldirish.
Redis CLI / Commands 
# Oxirgi 3 ta log yozuvini ko'rish
RPUSH logs "09:00 Auth" "09:05 Pay" "09:10 Error" "09:15 OK"
LRANGE logs 0 2
LRANGE logs -2 -1
⚡ Redis In-Memory CLI Natijasi:
💡 LTRIM logs 0 99 buyrug'i orqali ro'yxatni doimiy ravishda so'nggi 100 ta yozuv bilan cheklab turish mumkin.

Lists Redis Mavzu #11

LPOP va RPOP: Navbat va Stek Amallari

Ro'yxatdan elementlarni sug'urib olish orqali navbat (FIFO) va stek (LIFO) ma'lumotlar tuzilmalarini osongina yaratish mumkin.

  • LPOP key — chapdagi eng birinchi elementni olib tashlaydi va qaytaradi.
  • RPOP key — o'ngdagi eng oxirgi elementni olib tashlaydi va qaytaradi.
  • BLPOP key timeout — bloklovchi o'qish (navbatda element paydo bo'lguncha kutib turadi).
  • FIFO (Navbat): RPUSH orqali yozib, LPOP orqali qayta ishlash.
Redis CLI / Commands 
# Navbatdan vazifani qayta ishlash uchun olish
RPUSH tasks "sms_yuborish" "rasm_qisqartirish"
LPOP tasks
LPOP tasks
LPOP tasks
⚡ Redis In-Memory CLI Natijasi:
💡 Ro'yxat bo'shab qolsa LPOP (nil) qaytaradi. BLPOP esa yangi element kelishini belgilangan sekundgacha kutadi.

Lists Redis Mavzu #12

LLEN: Ro'yxat Uzunligini O'lchash

LLEN ro'yxatdagi jami elementlar sonini O(1) doimiy vaqt ichida hisoblab beradi.

  • LLEN key — ro'yxat uzunligini qaytaradi.
  • Agar kalit mavjud bo'lmasa 0 qaytadi.
  • Navbatda qancha ish qolganligini monitoring qilish uchun ishlatiladi.
Redis CLI / Commands 
# Kutilayotgan xabarlar sonini bilish
RPUSH queue:sms "kod1" "kod2" "kod3"
LLEN queue:sms
⚡ Redis In-Memory CLI Natijasi:

Hashes Redis Mavzu #13

HSET va HGET: Hash Xaritalari

Redis Hash — bu kalit-qiymat juftliklaridan iborat ob'ektdir. U foydalanuvchi profillari, mahsulot tafsilotlari kabi tuzilmali ma'lumotlarni saqlash uchun mo'ljallangan.

  • HSET key field value [field value...] — ob'ekt maydonlarini saqlash.
  • HGET key field — aniq bir maydon qiymatini olish.
  • HMGET key field1 field2... — bir nechta maydonlarni olish.
  • Har bir maydon uchun alohida String kalit yaratgandan ko'ra Hash 5 barobar kam xotira sarflaydi.
Redis CLI / Commands 
# Foydalanuvchi profilini saqlash
HSET user:101 ism "Azizbek" yosh 22 kasb "Frontend" shahar "Toshkent"

# Alohida maydonlarni olish
HGET user:101 ism
HMGET user:101 yosh kasb
⚡ Redis In-Memory CLI Natijasi:
💡 JSON matnini butunligicha saqlagandan ko'ra Hash qulay, chunki faqat bitta maydonni butun ob'ektni qayta yozmasdan yangilash mumkin.

Hashes Redis Mavzu #14

HGETALL, HKEYS va HVALS

Hash ichidagi barcha maydon va qiymatlarni birvarakayiga olish uchun HGETALL ishlatiladi.

  • HGETALL key — barcha maydon va qiymat juftliklarini chiqaradi.

  • HVALS key — faqat qiymatlarni (values) oladi.
  • HLEN key — ob'ektdagi maydonlar sonini ko'rsatadi.
Redis CLI / Commands 
# Ob'ektning butun tarkibini chiqarish
HGETALL user:101
HKEYS user:101

HDEL va HEXISTS: Hash Boshqaruvi

Hash ob'ektidan keraksiz maydonlarni o'chirish yoki maydon mavjudligini tekshirish usullari.

  • HDEL key field... — ko'rsatilgan maydonni o'chirish.

Sets Redis Mavzu #16

SADD va SMEMBERS: To'plamlar (Sets)

Redis Set — bu takrorlanmas (unique) elementlarning tartiblanmagan to'plamidir. Bir xil qiymat bir necha bor qo'shilsa ham faqat 1 marta saqlanadi.

  • SADD key member... — to'plamga elementlar kiritish.
  • SMEMBERS key — to'plamdagi barcha elementlarni olish.
  • SCARD key — to'plamdagi elementlar sonini hisoblash.
  • Teglar (Tags), onlayn foydalanuvchilar ID lari, do'stlar ro'yxati uchun ideal.
Redis CLI / Commands 
# Kitob teglarini saqlash (takrorlar e'tiborga olinmaydi)
SADD book:1:tags "dasturlash" "javascript" "web" "dasturlash"

# Elementlar va ularning soni
SMEMBERS book:1:tags
SCARD book:1:tags
⚡ Redis In-Memory CLI Natijasi:
💡 E'tibor bering: 'dasturlash' ikki marta yozilgan bo'lsa-da, faqat bir marta qo'shildi va soni 3 ta bo'ldi.

Sets Redis Mavzu #17

SINTER, SUNION va SDIFF: To'plam Amallari

Matematik to'plam amallari (kesishma, birlashma, ayirma) Redis da O(N) tezlikda to'g'ridan-to'g'ri serverda bajariladi.

  • SINTER key1 key2 — kesishma (umumiy umumiy do'stlar, o'xshash qiziqishlar).
  • SUNION key1 key2 — birlashma (barcha qatnashgan elementlar).
  • SDIFF key1 key2 — ayirma (birinchisida bor, ikkinchisida yo'q).
Redis CLI / Commands 
# Ikki foydalanuvchining ko'nikmalari
SADD skills:ali "Python" "Docker" "Redis" "Linux"
SADD skills:vali "JavaScript" "React" "Docker" "Redis"

# Umumiy ko'nikmalarni topish (Kesishma)
SINTER skills:ali skills:vali

# Faqat Alida bor ko'nikmalar (Ayirma)
SDIFF skills:ali skills:vali
⚡ Redis In-Memory CLI Natijasi:
💡 Ijtimoiy tarmoqlardagi 'Umumiy do'stlar' (Mutual Friends) funksiyasi aynan SINTER yordamida mikrosekundlarda topiladi.

Sets Redis Mavzu #18

SREM va SISMEMBER

To'plamdan elementni o'chirish va uning a'zoligini bir zumda tekshirish usullari.

  • SISMEMBER key member — element to'plamda bormi? (1 = ha, 0 = yo'q). Tezlik: O(1).
  • SREM key member — elementni to'plamdan o'chirish.
  • SPOP key — to'plamdan tasodifiy elementni sug'urib olish (lotoreya, yutuqli o'yinlar uchun).
Redis CLI / Commands 
# Ruxsat berilgan IP manzillarni tekshirish
SADD whitelist:ips "192.168.1.1" "10.0.0.5"
SISMEMBER whitelist:ips "192.168.1.1"
SISMEMBER whitelist:ips "172.16.0.1"

# O'chirish
SREM whitelist:ips "10.0.0.5"
⚡ Redis In-Memory CLI Natijasi:
💡 SISMEMBER yordamida qora ro'yxat (Blacklist) yoki oq ro'yxatni (Whitelist) O(1) doimiy vaqtda tekshirish mumkin.

Sorted Sets Redis Mavzu #19

ZADD: Tartiblangan To'plamlar (Sorted Sets)

Sorted Set (ZSet) — har bir a'zosi ballga (score) ega bo'lgan to'plam. Barcha a'zolar avtomatik ravishda ballari bo'yicha saralangan holda saqlanadi.

  • ZADD key score member... — ball va elementni qo'shish.
  • O'yinlardagi peshqadamlar jadvali (Leaderboard), mahsulotlar reytingi va qidiruv natijalarini saralash uchun eng kuchli mexanizm.
  • Skip List va Hash Table asosida ishlaydi, qidirish va kiritish tezligi O(log(N)).
Redis CLI / Commands 
# O'yin liderlar jadvaliga o'yinchilar qo'shish
ZADD leaderboard 1500 "Rustam" 2200 "Malika" 1850 "Jasur" 3100 "Botir"

# Jami o'yinchilar soni
ZCARD leaderboard
⚡ Redis In-Memory CLI Natijasi:
💡 Agar bir xil o'yinchi boshqa ball bilan qayta ZADD qilinsa, uning bali avtomatik yangilanadi va o'rni qayta hisoblanadi.

Sorted Sets Redis Mavzu #20

ZSCORE va ZRANGE: Ballar Bo'yicha Saralash

Elementning ballini olish va liderlar ro'yxatini pastdan yuqoriga yoki yuqoridan pastga qarab chiqarish amallari.

  • ZSCORE key member — o'yinchining joriy balini ko'rsatish.
  • ZRANGE key start stop [WITHSCORES] — kichik balldan kattasiga saralash.
  • ZREVRANGE key start stop [WITHSCORES] — eng yuqori balldan pastiga saralash (Top 10 uchun).
  • ZINCRBY key increment member — o'yinchiga qo'shimcha ball qo'shish.
Redis CLI / Commands 
# Malikaning balini ko'rish
ZSCORE leaderboard "Malika"

# Eng kuchli 3 ta o'yinchini ballari bilan chiqarish
ZREVRANGE leaderboard 0 2 WITHSCORES
⚡ Redis In-Memory CLI Natijasi:
💡 ZREVRANGE 0 9 WITHSCORES buyrug'i millionlab o'yinchilar orasidan bir lahzada Top-10 reytingni qaytaradi.

Sorted Sets Redis Mavzu #21

ZRANK va ZREVRANK: O'rinni Belgilash

Foydalanuvchining butun platforma bo'yicha nechanchi o'rinda turganligini aniqlash.

  • ZREVRANK key member — yuqoridan pastga (eng kattasi 0-o'rin) bo'yicha o'rin.
  • ZRANK key member — pastdan yuqoriga bo'yicha o'rin.

Arxitektura Redis Mavzu #24

Redis Doimiyligi: RDB va AOF

Redis xotira to'xtaganda ma'lumotlar yo'qolib ketmasligi uchun ma'lumotlarni qattiq diskka yozib borishning 2 ta kuchli mexanizmini taqdim etadi.

  • RDB (Redis Database Snapshot): Belgilangan vaqt oralig'ida (masalan, har 5 daqiqada) xotiraning to'liq rasmini diskka dump.rdb fayli qilib saqlaydi. Juda ixcham.
  • AOF (Append Only File): Barcha yozish buyruqlarini (SET, HSET va h.k.) jurnal fayliga qo'shib boradi (appendonly.aof). Minimal ma'lumot yo'qotish.
  • Eng yaxshi amaliyot: Ikkala usulni birgalikda yoqib qo'yish (Hybrid Persistence).

Kesh Redis Mavzu #25

Redis Kesh Strategiyalari (Cache-Aside)

Web ilovalarda Redis dan to'g'ri foydalanishning eng mashhur arxitektura namunasi Cache-Aside (Lazy Loading) hisoblanadi.

  • 1. Dastur so'rov olganda avval keshni (Redis) tekshiradi.
  • 2. Agar ma'lumot keshda bo'lsa (Cache Hit), uni darhol mijozga qaytaradi.
  • 3. Agar keshda bo'lmasa (Cache Miss), asosiy bazadan (PostgreSQL) o'qiydi, keshga (Redis) TTL bilan yozadi va mijozga qaytaradi.
  • Natijada asosiy bazaga tushadigan yuklama 90% ga kamayadi.
Redis CLI / Commands 
// Cache-Aside namunasi (Pseudo-kod)
async function getProduct(id) {
  const cacheKey = `product:${id}`;
  
  // 1. Keshdan qidiramiz
  const cached = await redis.get(cacheKey);
  if (cached) {
    return JSON.parse(cached); // Cache Hit ⚡
  }
  
  // 2. Asosiy bazadan olamiz (Cache Miss)
  const product = await db.query("SELECT * FROM products WHERE id = $1", [id]);
  
  // 3. Redis ga 1 soatga (3600s) keshlab qo'yamiz
  await redis.setex(cacheKey, 3600, JSON.stringify(product));
  
  return product;
}
⚡ Redis In-Memory CLI Natijasi:
💡 Kesh yangilanishi uchun mahsulot tahrirlanganda keshdagi kalitni o'chirib (DEL product:id) tashlash lozim (Cache Invalidation).

// Node.js (ioredis) namunasi:
const Redis = require('ioredis');
const redis = new Redis({
  host: '127.0.0.1',
  port: 6379
});

async function main() {
  await redis.set('platform', 'W3Learn.uz', 'EX', 3600);
  const value = await redis.get('platform');
  console.log('Keshdan olingan qiymat:', value);

  // Hash bilan ishlash
  await redis.hset('user:42', 'name', 'Sherzod', 'role', 'Admin');
  const user = await redis.hgetall('user:42');
  console.log('Foydalanuvchi obyekti:', user);
}

main();
