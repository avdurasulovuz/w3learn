Asosiy MongoDB Mavzu #1

MongoDB Nima? NoSQL va Hujjatli Baza

MongoDB — dunyodagi eng mashhur ochiq kodli NoSQL (Not Only SQL) hujjatlarga asoslangan ma'lumotlar bazasidir. Unda qat'iy SQL jadvallari o'rniga ma'lumotlar xuddi JSON kabi ko'rinishga ega bo'lgan BSON (Binary JSON) formatidagi moslashuvchan hujjatlar (Documents) ko'rinishida saqlanadi.

  • Sxemasiz (Schema-less): har bir hujjat har xil maydonlarga ega bo'lishi mumkin.
  • Tuzilma taqqoslash: SQL Database -> MongoDB Database; SQL Table -> MongoDB Collection; SQL Row -> MongoDB Document; SQL Column -> MongoDB Field.
  • MERN (MongoDB, Express, React, Node.js) stekining asosiy ma'lumotlar ombori.
  • Gorizontal kengayish (Sharding) orqali terabaytlab ma'lumotlarni oson boshqaradi.
MongoDB / mongosh 
// MongoDB BSON hujjati namunasi:
{
  "_id": ObjectId("655f1a8b9a1e4c3d2e1f0001"),
  "ism": "Jasur Aliyev",
  "yosh": 24,
  "konikmalar": ["JavaScript", "Node.js", "MongoDB"],
  "manzil": {
    "shahar": "Toshkent",
    "tuman": "Chilonzor"
  },
  "faolmi": true
}
🍃 MongoDB Shell / Server Natijasi:
💡 Relyatsion bazalarda 3 ta bog'langan jadval (users, addresses, skills) kerak bo'lgan vazifani MongoDB bitta hujjat ichida hal qiladi.

MongoDB O'rnatish va mongosh Terminali

Cloud MongoDB Mavzu #3

MongoDB Atlas — Bulutli Ma'lumotlar Bazasi (Cloud)

MongoDB Atlas — bu hech qanday dastur o'rnatmasdan turib AWS, Google Cloud yoki Azure bulutlarida MongoDB klasterini bepul ishga tushirish imkonini beruvchi to'liq boshqariladigan DBaaS (Database-as-a-Service) xizmatidir.

  • 512 MB bepul xotira (M0 Sandbox) har qanday o'quv va portfolio loyihalar uchun yetarli.
  • Avtomatik zaxira nusxalash (Backup) va SSL xavfsizlik sertifikatlari.
  • Ulanish havolasi (Connection String): mongodb+srv://admin:<password>@cluster0.mongodb.net/myDb.

// mongoose.connect(uri);

CRUD MongoDB Mavzu #5

insertOne va insertMany — Hujjat Qo'shish

Kolleksiyaga bitta hujjat qo'shish uchun insertOne(), bir vaqtning o'zida massiv ko'rinishida bir nechta hujjat kiritish uchun insertMany() ishlatiladi.

  • Agar hujjatda _id ko'rsatilmasa, MongoDB unga 12-baytli noyob ObjectId ni avtomatik yaratadi.
  • Kolleksiya mavjud bo'lmasa, ma'lumot qo'shilganda avtomatik yaratiladi.
MongoDB / mongosh 
// Bitta foydalanuvchi qo'shish
db.foydalanuvchilar.insertOne({
  ism: "Olim",
  familiya: "Shokirov",
  email: "olim@w3learn.uz",
  yosh: 21,
  ballar: [85, 92, 78]
});

// Bir nechta foydalanuvchini qo'shish
db.foydalanuvchilar.insertMany([
  { ism: "Nodira", email: "nodira@uz", yosh: 19 },
  { ism: "Bobur", email: "bobur@uz", yosh: 25 }
]);
🍃 MongoDB Shell / Server Natijasi:
⚡ insertMany() katta hajmdagi ma'lumotlarni yozishda insertOne() ni siklda aylantirishga nisbatan ancha tez ishlaydi.

CRUD MongoDB Mavzu #6

find va findOne — Hujjatlarni Qidirish

Kolleksiyadan ma'lumotlarni o'qish uchun find() (barcha mos keluvchilar) va findOne() (faqat birinchi topilgan bitta hujjat) ishlatiladi.

  • Barcha hujjatlarni olish: db.foydalanuvchilar.find().
  • Chiroyli formatda chiqarish: .pretty().
  • Shart bo'yicha qidirish: db.foydalanuvchilar.find({ ism: "Olim" }).
  • Ichki ob'ekt bo'yicha qidirish nuqta orqali: { "manzil.shahar": "Samarqand" }.
MongoDB / mongosh 
// Barcha foydalanuvchilarni qidirish
db.foydalanuvchilar.find();

// Aniq bittasini topish
db.foydalanuvchilar.findOne({ email: "olim@w3learn.uz" });
🍃 MongoDB Shell / Server Natijasi:
💡 Agar find({}) bo'sh qavs bilan chaqirilsa, SQL dagi SELECT * kabi barcha hujjatlarni qaytaradi.

CRUD MongoDB Mavzu #7

updateOne va updateMany — $set va $inc Operatorlari

Hujjatlarni yangilashda to'g'ridan-to'g'ri yangi ob'ekt yozib yuborilsa butun hujjat o'chib yangisiga almashib qolishi mumkin. Shuning uchun maxsus $set va $inc atomik operatorlari ishlatiladi.

  • $set: ko'rsatilgan maydon qiymatini o'zgartiradi yoki bo'lmasa yangi maydon qo'shadi.
  • $inc: sonli maydonni ko'rsatilgan miqdorga oshiradi (masalan yoshini +1 ga).
  • $push: massiv ichiga yangi element qo'shish.
  • upsert: true: agar bunday hujjat topilmasa yangisini yaratadi.
MongoDB / mongosh 
// Olimning yoshini 22 qilish va yangi telefon maydoni qo'shish
db.foydalanuvchilar.updateOne(
  { email: "olim@w3learn.uz" },
  { 
    $set: { telefon: "+998901234567" },
    $inc: { yosh: 1 } // yosh = yosh + 1
  }
);
🍃 MongoDB Shell / Server Natijasi:
🔒 Hech qachon $set siz oddiy { yosh: 22 } deb yangilamang, aks holda boshqa barcha maydonlar o'chib ketadi!

CRUD MongoDB Mavzu #8

deleteOne va deleteMany — Hujjatlarni O'chirish

Kolleksiyadan hujjatlarni o'chirish uchun deleteOne() (shartga mos kelgan birinchi hujjatni) va deleteMany() (mos keluvchi barchasini) ishlatiladi.

  • ID bo'yicha o'chirish: db.kolleksiya.deleteOne({ _id: ObjectId("...") }).
  • Shartli o'chirish: db.kolleksiya.deleteMany({ faolmi: false }).
  • Barcha hujjatlarni tozalash: db.kolleksiya.deleteMany({}).
MongoDB / mongosh 
// Faol bo'lmagan foydalanuvchilarni o'chirish
db.foydalanuvchilar.deleteMany({ faolmi: false });

// Natijani tekshirish
print("O'chirildi!");
🍃 MongoDB Shell / Server Natijasi:
⚡ Agar butun kolleksiyani yo'q qilmoqchi bo'lsangiz, deleteMany({}) dan ko'ra db.kolleksiya.drop() buyrug'i minglab marta tezroq ishlaydi.

Filtr MongoDB Mavzu #9

Filter Operatorlari — $gt, $lt, $in, $and, $or

MongoDB taqqoslash va mantiqiy amallarni bajarish uchun maxsus dollar belgisi bilan boshlanuvchi operatorlarni taqdim etadi.

  • Taqqoslash: $gt (>), $gte (>=), $lt (<), $lte (<=), $ne (!=).
  • Ro'yxat tekshiruvi: $in: [18, 20, 25] va $nin.
  • Mantiqiy: $and: [{...}, {...}], $or: [{...}, {...}], $not.
MongoDB / mongosh 
// Yoshi 20 dan 25 gacha bo'lgan yoki Toshkentlik talabalarni topish
db.foydalanuvchilar.find({
  $or: [
    { yosh: { $gte: 20, $lte: 25 } },
    { "manzil.shahar": "Toshkent" }
  ]
});
🍃 MongoDB Shell / Server Natijasi:
💡 Bitta maydonga bir nechta shart berilganda (masalan { yosh: { $gte: 18, $lte: 30 } }) ular avtomatik ravishda AND mantiqi bilan ishlaydi.

Qidiruv MongoDB Mavzu #10

sort, limit va skip — Saralash va Sahifalash

Qidiruv natijalarini saralash uchun sort(), sonini cheklash uchun limit() va boshidan o'tkazib yuborish uchun skip() metodlari zanjir (chain) ko'rinishida qo'llaniladi.

  • O'sish tartibida: sort({ yosh: 1 }).
  • Kamayish tartibida: sort({ yosh: -1 }).
  • Sahifalash formulasi: skip((page - 1) * limit).limit(limit).
MongoDB / mongosh 
-- Eng yoshi katta 3 ta foydalanuvchini olish (2-sahifa)
db.foydalanuvchilar
  .find()
  .sort({ yosh: -1 })
  .skip(0)
  .limit(3);
🍃 MongoDB Shell / Server Natijasi:
⚡ Katta ma'lumotlar bazasida skip() sekinlashmasligi uchun saralanadigan ustunlarga albatta indeks o'rnatilishi shart.

Qidiruv MongoDB Mavzu #11

Projection — Faqat Kerakli Maydonlarni Olish

Projection — bu SQL dagi ustunlarni tanlash (SELECT ism, email) ga teng. U tarmoq trafigini tejash uchun hujjatning faqat o'zingizga kerakli maydonlarini olib, qolganlarini tashlab yuborish imkonini beradi.

  • Ko'rsatish: { maydon: 1 }.
  • Yashirish: { maydon: 0 }.
  • _id maydoni sukut bo'yicha doimo chiqadi, uni yashirish uchun alohida _id: 0 yozish kerak.
MongoDB / mongosh 
// Faqat ism va emailni olish (_id ni yashirish)
db.foydalanuvchilar.find(
  { yosh: { $gte: 20 } },       // 1-parametr: Shart (WHERE)
  { ism: 1, email: 1, _id: 0 }   // 2-parametr: Projection (SELECT)
);
🍃 MongoDB Shell / Server Natijasi:
💡 Bitta projection ichida 1 va 0 larni aralashtirib yozib bo'lmaydi (yagona istisno: _id: 0).

Qidiruv MongoDB Mavzu #12

Regex Qidiruv ($regex) — Matn Bo'yicha Qidiruv

Muntazam ifodalar (Regular Expressions) yordamida matnning boshlanishi, tugashi yoki biror so'zni o'z ichiga olishi bo'yicha qulay qidiruv amalga oshiriladi.

  • Katta-kichik harf farqsiz (Case-insensitive): $options: "i".
  • Boshlanishi bo'yicha: /^Ali/.
  • Gmail manzillarini topish: /@gmail\.com$/i.
MongoDB / mongosh 
// Ismida 'lim' bo'lganlarni harf kattaligidan qat'i nazar topish
db.foydalanuvchilar.find({
  ism: { $regex: "lim", $options: "i" }
});
🍃 MongoDB Shell / Server Natijasi:
⚡ Katta matnlarni tezkor qidirish uchun oddiy regex o'rniga MongoDB ning maxsus Text Index imkoniyatidan foydalanish tavsiya etiladi.

Aggregation MongoDB Mavzu #13

Aggregation Pipeline — Ma'lumotlarni Qayta Ishlash

Aggregation Pipeline — bu zavod konveyeri kabi ishlaydigan kuchli tahlil tizimidir. Hujjatlar bir bosqichdan (Stage) o'tib, keyingisiga filtrlanib, guruhlanib yoki o'zgartirilib uzatiladi.

  • Sintaksis: db.kolleksiya.aggregate([ { $stage1 }, { $stage2 }, ... ]).
  • Asosiy bosqichlar: $match, $group, $project, $sort, $lookup, $unwind.
  • Murakkab SQL so'rovlari va hisobotlar aynan Aggregation orqali yoziladi.
MongoDB / mongosh 
// Konveyer bosqichlari namunasi:
db.buyurtmalar.aggregate([
  // 1-bosqich: Faqat yakunlangan buyurtmalar
  { $match: { holat: "yakunlandi" } },
  
  // 2-bosqich: Mijozlar bo'yicha guruhlash va umumiy summani hisoblash
  { $group: { _id: "$mijoz_id", jami_summa: { $sum: "$narx" } } },
  
  // 3-bosqich: Eng ko'p xarid qilganlar bo'yicha saralash
  { $sort: { jami_summa: -1 } }
]);
🍃 MongoDB Shell / Server Natijasi:
🚀 Aggregation Pipeline MongoDB ning eng kuchli jihati bo'lib, uning yordamida istalgan murakkablikdagi analitik hisobotlarni tuzish mumkin.

Aggregation MongoDB Mavzu #14

$match — Pipeline da Filtrlash Bosqichi

$match bosqichi pipeline ning eng boshiga qo'yiladi va faqat kerakli hujjatlarni keyingi bosqichlarga o'tkazish uchun filtr vazifasini bajaradi (SQL dagi WHERE ga teng).

  • Pipeline boshida $match qo'yish indekslardan foydalanish imkonini beradi va tezlikni 10 barobar oshiradi.
  • Barcha standart filter operatorlari ($gt, $in va h.k.) bu yerda ham ishlaydi.
MongoDB / mongosh 
db.mahsulotlar.aggregate([
  {
    $match: {
      kategoriya: "Elektronika",
      narx: { $gte: 1000000 }
    }
  }
]);
🍃 MongoDB Shell / Server Natijasi:
💡 Har doim $match ni pipeline ning imkon qadar eng boshiga qo'ying!

Aggregation MongoDB Mavzu #15

$group — Guruhlarga Ajratish va Hisoblash

$group bosqichi hujjatlarni biror umumiy kalit (_id) bo'yicha guruhlaydi va hisob-kitoblar (COUNT, SUM, AVG, MIN, MAX) qiladi (SQL dagi GROUP BY ga teng).

  • _id: "$kategoriya" — qaysi maydon bo'yicha guruhlash.
  • $sum: 1 — qatorlar sonini sanash (COUNT).
  • $avg: "$narx" — o'rtacha narx.
  • $push: "$nomi" — guruhdagi barcha nomlarni bitta massivga to'plash.
MongoDB / mongosh 
// Har bir shahar bo'yicha foydalanuvchilar soni va o'rtacha yoshi
db.foydalanuvchilar.aggregate([
  {
    $group: {
      _id: "$manzil.shahar",
      foydalanuvchilarSoni: { $sum: 1 },
      ortachaYosh: { $avg: "$yosh" }
    }
  }
]);
🍃 MongoDB Shell / Server Natijasi:
⚡ Agar butun kolleksiya bo'yicha bitta umumiy hisob-kitob kerak bo'lsa, _id: null qilib guruhlanadi.

Aggregation MongoDB Mavzu #16

$lookup — Kolleksiyalarni Bog'lash (MongoDB dagi JOIN)

NoSQL da jadvallar yo'q bo'lsa ham, ba'zan turli kolleksiyalardagi ma'lumotlarni o'zaro bog'lash zarur bo'ladi. Buni $lookup bosqichi bajaradi (SQL dagi LEFT JOIN ga teng).

  • from: ulanayotgan ikkinchi kolleksiya nomi.
  • localField: joriy kolleksiyadagi bog'lovchi kalit.
  • foreignField: ikkinchi kolleksiyadagi kalit.
  • as: topilgan ma'lumotlar saqlanadigan yangi massiv nomi.
MongoDB / mongosh 
// Buyurtmalarga mijoz ma'lumotlarini birlashtirish
db.buyurtmalar.aggregate([
  {
    $lookup: {
      from: "foydalanuvchilar",
      localField: "mijoz_id",
      foreignField: "_id",
      as: "mijoz_haqida"
    }
  }
]);
🍃 MongoDB Shell / Server Natijasi:
💡 $lookup natijasida kelgan massivni bitta ob'ektga aylantirish uchun undan keyin { $unwind: "$mijoz_haqida" } bosqichi qo'yiladi.

Aggregation MongoDB Mavzu #17

$project — Ma'lumotlarni Qayta Formatlash

$project bosqichi yakuniy natijada qaysi maydonlar ko'rinishini belgilaydi, yangi hisoblangan maydonlar (Computed fields) hosil qiladi va maydon nomlarini o'zgartiradi.

  • Matnlarni birlashtirish: { $concat: ["$ism", " ", "$familiya"] }.
  • Shartli qiymat berish: $cond.
  • Keraksiz maydonlarni yashirish: { maxfiy_kod: 0 }.
MongoDB / mongosh 
db.foydalanuvchilar.aggregate([
  {
    $project: {
      _id: 0,
      toliqIsm: { $concat: ["$ism", " ", "$familiya"] },
      yosh: 1,
      kattami: { $gte: ["$yosh", 18] }
    }
  }
]);
🍃 MongoDB Shell / Server Natijasi:
⚡ $project yordamida frontend ga aynan kerakli chiroyli formatdagi JSON ma'lumot yetkazib beriladi.

Mongoose MongoDB Mavzu #18

Mongoose Kirish — Node.js ODM Kutubxonasi

Mongoose — bu Node.js dasturchilari uchun MongoDB bilan ishlashning eng mashhur va qulay ODM (Object Data Modeling) kutubxonasidir. U sxemasiz MongoDB ga qat'iy ma'lumotlar sxemasi (Schema), turlar tekshiruvi va mantiqiy metodlarni olib keladi.

  • O'rnatish: npm install mongoose.
  • Ulanish: mongoose.connect('mongodb://localhost:27017/mydb').
  • Barcha operatsiyalar zamonaviy async / await asosida ishlaydi.
  • Ma'lumotlar bazasi xatolarini avtomatik ushlaydi va tozalaydi.
MongoDB / mongosh 
// app.js (Node.js)
const mongoose = require('mongoose');

async function main() {
  await mongoose.connect('mongodb://127.0.0.1:27017/w3learn');
  console.log("MongoDB ga muvaffaqiyatli ulandi! 🍃");
}

main().catch(err => console.log("Xatolik:", err));
🍃 MongoDB Shell / Server Natijasi:
💡 Mongoose Node.js loyihalarida MongoDB bilan ishlashning de-fakto standarti hisoblanadi.

Mongoose MongoDB Mavzu #19

Schema va Model Yaratish (Mongoose)

Mongoose da har bir kolleksiya uchun avval Schema (maydonlar va ularning tiplari qolipi), so'ngra shu sxema asosida ma'lumotlarni boshqaruvchi Model klassi yaratiladi.

  • Sxema turlari: String, Number, Boolean, Date, Array, ObjectId.
  • Model yaratish: const User = mongoose.model('User', userSchema);.
  • MongoDB avtomatik ravishda 'User' nomini ko'plikda kichik harflar bilan 'users' kolleksiyasiga aylantiradi.
MongoDB / mongosh 
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
  ism: { type: String, required: true },
  email: { type: String, required: true, unique: true },
  yosh: { type: Number, min: 14, max: 100 },
  rol: { type: String, enum: ['user', 'admin'], default: 'user' }
}, { timestamps: true }); // createdAt va updatedAt avtomatik qo'shiladi

const User = mongoose.model('User', userSchema);
🍃 MongoDB Shell / Server Natijasi:
⚡ { timestamps: true } opsiyasi hujjat yaratilgan va oxirgi marta yangilangan sanani avtomatik qayd etadi.

Mongoose MongoDB Mavzu #22

Mongoose Middleware — Pre va Post Hooklar

Mongoose Middleware (Pre va Post hooklar) — bu biror amal (masalan save, remove, updateOne) bajarilishidan oldin yoki keyin avtomatik ishga tushuvchi funksiyalardir.

  • Eng mashhur qo'llanishi: Parolni bazaga saqlashdan oldin avtomatik bcrypt bilan xesh qilish.
  • schema.pre('save', async function() { ... }).
  • schema.post('save', function(doc) { ... }).
MongoDB / mongosh 
const bcrypt = require('bcryptjs');

// Saqlashdan oldin parolni xesh qilish
userSchema.pre('save', async function() {
  // Faqat parol o'zgargan bo'lsagina qayta xesh qilinadi
  if (!this.isModified('parol')) return;
  
  const salt = await bcrypt.genSalt(10);
  this.parol = await bcrypt.hash(this.parol, salt);
  console.log("Parol xavfsiz xesh qilindi 🔒");
});

Xavfsizlik MongoDB Mavzu #24

MongoDB Tranzaksiyalari — Multi-Document ACID

MongoDB 4.0 versiyasidan boshlab relyatsion bazalardagi kabi Multi-Document ACID Tranzaksiyalari ni qo'llab-quvvatlaydi. Agar bir nechta hujjatlar orasida pul o'tkazish yoki buyurtma rasmiylashtirish kerak bo'lsa, tranzaksiya barcha amallarning xatosiz o'tishini ta'minlaydi.

  • Sessiya boshlash: const session = await mongoose.startSession();.
  • Tranzaksiyani boshlash: session.startTransaction();.
  • Tasdiqlash: await session.commitTransaction();.
  • Bekor qilish: await session.abortTransaction();.
MongoDB / mongosh 
const session = await mongoose.startSession();
session.startTransaction();

try {
  // 1-amal: Pul yechish
  await Hisob.updateOne({ _id: userA }, { $inc: { balans: -50000 } }, { session });
  
  // 2-amal: Pul qo'shish
  await Hisob.updateOne({ _id: userB }, { $inc: { balans: 50000 } }, { session });

  await session.commitTransaction();
  console.log("Tranzaksiya muvaffaqiyatli yakunlandi! 💵");
} catch (error) {
  await session.abortTransaction();
  console.log("Xatolik yuz berdi, barcha amallar bekor qilindi!");
} finally {
  session.endSession();
}

Replikatsiya — Replica Set va Yuqori Bardoshlilik

Replication (Nusxalash) — bu bitta ma'lumotlar bazasining nusxalarini bir nechta mustaqil serverlarda saqlash usulidir. Bu serverlardan biri yonib ketsa yoki elektr o'chsa ham, tizim bir lahzaga ham to'xtamasligini (High Availability) ta'minlaydi.

  • Primary (Asosiy): barcha yozish (write) amallarini qabul qiladi.
  • Secondary (Qo'shimcha): asosiy tugundan ma'lumotlarni o'ziga nusxalab turadi va o'qish (read) yuklamasini bo'lishadi.
  • Avtomatik saylov (Failover): agar Primary server ishdan chiqsa, qolgan Secondary serverlar bir necha soniyada yangi Primary ni o'zlari saylab oladi.

Klaster MongoDB Mavzu #26

Sharding — Gorizontal Kengayish (Masshtablash)

Ma'lumotlar hajmi bitta kompyuterning qattiq diskiga yoki xotirasiga sig'maydigan darajada ulkan bo'lib ketganda (petabaytlar darajasida), Sharding texnologiyasi ishga tushadi. U ma'lumotlarni bir nechta mustaqil serverlar (Shardlar) orasida taqsimlab saqlaydi.

  • Vertikal masshtablash: bitta kompyuterni kuchaytirish (chegarasi bor, qimmat).
  • Gorizontal masshtablash (Sharding): yangi arzon serverlarni klasterga qo'shish (cheksiz kengayish).
  • Shard Key: ma'lumotlar aynan qaysi serverga tushishini belgilovchi maxsus ustun (masalan mamlakat kodi yoki user_id).
  • Mongos Router: so'rovlarni kerakli Shard ga yo'naltiruvchi yuklama taqsimlagich.
MongoDB / mongosh 
// Kolleksiyada Sharding ni yoqish
sh.enableSharding("w3learn_db");

// Shard kaliti bo'yicha taqsimlash
sh.shardCollection("w3learn_db.foydalanuvchilar", { "mamlakat": 1, "_id": 1 });
