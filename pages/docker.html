Asosiy Docker Mavzu #1

Docker Nima? Konteynerlashtirish Inqilobi

Docker — dasturlarni ularning barcha kutubxonalari, muhiti va bog'liqliklari bilan birga yengil, mustaqil konteyner ichiga joylash imkonini beruvchi platformadir. U dasturchilarning afsonaviy 'Mening kompyuterimda ishlayotgan edi-ku!' degan muammosiga abadiy chek qo'ydi.

  • Virtual Mashinalardan (VM) farqi: Docker alohida OS yadrosini virtualizatsiya qilmaydi, balki bitta umumiy Linux yadrosi ustida izolyatsiyalangan jarayonlar sifatida ishlaydi.
  • Yengil va tez: Konteynerlar bir necha soniyada ishga tushadi va bir necha megabayt xotira sarflaydi.
  • Standartlashtirish: Dastur ishlab chiquvchining noutbukida qanday ishlasa, test va production serverda ham xuddi shunday ishlaydi.
  • Mikroservislar arxitekturasi va zamonaviy DevOps ning asosi hisoblanadi.
Docker CLI / Dockerfile 
# Docker versiyasini tekshirish
docker --version

# Birinchi sinov konteynerini ishga tushirish
docker run hello-world
🐳 Docker Engine Chiqarishi:
💡 Docker konteyneri o'z ichida operatsion tizim kutubxonalari va dastur kodini to'liq saqlagani uchun boshqa serverga ko'chirish juda oson.

O'rnatish Docker Mavzu #2

Docker O'rnatish: Desktop va Engine

Docker ni turli operatsion tizimlarga o'rnatish usullari.

  • Windows va macOS: Docker Desktop (GUI interfeys va WSL 2 integratsiyasi bilan).
  • Linux (Ubuntu/Debian): Docker Engine rasmiy omboridan apt orqali o'rnatiladi.
  • Foydalanuvchini docker guruhiga qo'shish (Linuxda sudo siz ishlash uchun): sudo usermod -aG docker $USER.
Docker CLI / Dockerfile 
# Ubuntu tizimida Docker Engine o'rnatish
sudo apt update
sudo apt install -y ca-certificates curl gnupg
# Docker xizmatini yoqish
sudo systemctl enable docker
sudo systemctl start docker
🐳 Docker Engine Chiqarishi:
💡 Windows tizimida Docker Desktop to'g'ri ishlashi uchun 'WSL 2' funksiyasi yoqilgan bo'lishi kerak.

Arxitektura Docker Mavzu #3

Docker Arxitekturasi (Client-Server)

Docker klassik Client-Server arxitekturasida ishlaydi.

  • Docker Client (CLI): Dasturchi terminalda yozadigan buyruqlar (docker run, docker build).
  • Docker Daemon (dockerd): Orqa fonda yuruvchi asosiy server jarayoni. U imidjlar, konteynerlar, tarmoqlar va disklarni yaratadi va boshqaradi.
  • Docker Host: Daemon ishlayotgan jismoniy yoki virtual mashina.
  • Docker Registry: Imidjlar saqlanadigan bulutli ombor (Docker Hub).
Docker CLI / Dockerfile 
# Docker tizim ma'lumotlarini ko'rish
docker info
🐳 Docker Engine Chiqarishi:
💡 Docker CLI REST API orqali Docker Daemon bilan bog'lanadi; bu degani bitta kompyuterdan turib boshqa serverdagi dockerd ni ham boshqarish mumkin.

Tushunchalar Docker Mavzu #4

Asosiy Tushunchalar: Image vs Container

Docker bilan ishlashda eng muhim 4 ta atama bor:

  • Image (Imidj): Dasturning statik nusxasi, 'retsepti' yoki shabloni (faqat o'qish uchun - Read-Only). Dasturlashdagi 'Klass'ga o'xshaydi.
  • Container (Konteyner): Imidjdan yaratilgan va ishga tushirilgan jonli jarayon (Read-Write qatlamiga ega). Dasturlashdagi 'Ob'ekt'ga o'xshaydi.
  • Volume (Disk): Konteyner o'chganda ham ma'lumotlar saqlanib qoladigan xotira maydoni.
  • Network (Tarmoq): Konteynerlarning o'zaro bir-biri bilan xavfsiz gaplashishi uchun virtual ko'prik.
Docker CLI / Dockerfile 
# Bitta Nginx imidjidan bir nechta konteyner ochish
docker run -d --name veb1 -p 8081:80 nginx
docker run -d --name veb2 -p 8082:80 nginx
🐳 Docker Engine Chiqarishi:
💡 Bitta imidjdan xohlagancha bir xil yoki har xil sozlamali konteynerlarni yaratish mumkin.

Imidjlar Docker Mavzu #5

Docker Image Tuzilishi va Qatlamlar (Layers)

Docker imidji bir-birining ustiga terilgan qatlamlardan (Layers) tashkil topadi. Har bir qatlam faqat o'qish uchun mo'ljallangan va keshlanadi.

  • Union File System (UnionFS) mexanizmi qatlamlarni birlashtirib, bitta yaxlit fayllar tizimiday ko'rsatadi.
  • Agar siz Dockerfile da faqat oxirgi satrni o'zgartirsangiz, Docker avvalgi barcha qatlamlarni keshdan (Cache) bir zumda oladi.
  • Bu esa imidjlarni yig'ish va yuklash vaqtini 10 barobarga qisqartiradi.
Docker CLI / Dockerfile 
# Imidj qatlamlari tarixini ko'rish
docker history nginx:alpine
🐳 Docker Engine Chiqarishi:
💡 Qatlamlar umumiy bo'lgani sababli, 10 ta turli dastur bitta Ubuntu bazasidan foydalansa, xotirada Ubuntu qatlami faqat 1 marta saqlanadi.

docker pull: Imidjlarni Yuklab Olish

Docker Hub (rasmiy ombor) dan kerakli dasturlarning imidjlarini mahalliy kompyuterga yuklab olish.

  • docker pull — eng oxirgi (latest) versiyani yuklaydi.
  • docker pull : — aniq ko'rsatilgan versiyani yuklaydi (masalan: node:20-alpine).
  • Production da hech qachon 'latest' ishlatmang, doim aniq versiya tegini belgilang.

docker pull redis:7-alpine
🐳 Docker Engine Chiqarishi:
💡 `alpine` qo'shimchali imidjlar Alpine Linux ga asoslangan bo'lib, hajmi o'ta ixcham bo'ladi (odatda 5-50 MB).

Imidjlar Docker Mavzu #8

docker rmi: Imidjlarni O'chirish

Keraksiz yoki eski imidjlarni diskdan o'chirish buyruqlari.

  • docker rmi -f — majburiy (force) o'chirish.

# Redis imidjini o'chirish

🐳 Docker Engine Chiqarishi:
💡 Avval o'sha imidjdan foydalanayotgan konteynerni o'chirib, keyin imidjni o'chirish xavfsiz usuldir.

Konteynerlar Docker Mavzu #9

docker run: Konteynerni Ishga Tushirish

docker run — Docker dagi eng asosiy buyruq. U ko'rsatilgan imidjni oladi va yangi konteyner yaratib ishga tushiradi.

  • -d (detached): Orqa fonda (fon rejimida) ishga tushirish.
  • -p tashqi_port:ichki_port: Portlarni bog'lash (port forwarding).
  • --name konteyner_nomi: Konteynerga tushunarli nom berish.
  • -e KALIT=QIYMAT: Muhit o'zgaruvchilari (Environment Variables) kiritish.
  • --rm: Konteyner to'xtaganda uni avtomatik o'chirib yuborish.
Docker CLI / Dockerfile 
# PostgreSQL konteynerini fon rejimida ishga tushirish
docker run -d \
  --name my-postgres \
  -p 5432:5432 \
  -e POSTGRES_PASSWORD=maxfiyparol \
  -e POSTGRES_DB=w3db \
  postgres:16-alpine
🐳 Docker Engine Chiqarishi:
💡 Natijada qaytgan uzun matn — bu yangi yaratilgan konteynerning 64 belgili noyob Container ID si hisoblanadi.

Konteynerlar Docker Mavzu #10

docker ps: Konteynerlar Monitoringi

Hozirda ishlayotgan yoki to'xtatilgan konteynerlar ro'yxatini ko'rish.

  • docker ps -a — barcha konteynerlarni (shu jumladan to'xtab turganlarini ham) ko'rsatadi.

docker stop va rm: Konteynerni Boshqarish

Konteynerlarni xavfsiz to'xtatish va diskdan butunlay olib tashlash.

  • docker stop — konteynerga SIGTERM signali yuborib, xavfsiz to'xtatadi.
  • docker start — to'xtab turgan konteynerni qayta uyg'otadi.

Konteynerlar Docker Mavzu #12

docker exec: Konteyner Ichiga Kirish

Ishlayotgan konteyner ichida yangi buyruq bajarish yoki interaktiv terminal (bash/sh) ochib, ichki fayllarni ko'rish.

  • -i (interactive): Standart kiritishni (STDIN) ochiq ushlab turadi.
  • -t (tty): Psevdor-terminal ajratadi.
  • docker exec -it sh (yoki bash) — konteyner ichidagi terminalga to'liq kirish.
Docker CLI / Dockerfile 
# PostgreSQL konteyneri ichiga kirib psql ni ishga tushirish
docker exec -it my-postgres psql -U postgres -d w3db

💡 Konteyner ichidan chiqish uchun oddiygina `exit` deb yoziladi.

docker logs: Loglarni Kuzatish

Dockerfile Docker Mavzu #14

Dockerfile Nima? Imidj Retsepti

Dockerfile — bu o'zingizning dasturingiz uchun maxsus Docker imidjini bosqichma-bosqich qanday qurish kerakligini bildiruvchi oddiy matnli fayldir.

  • Fayl kengaytmasiz, aniq Dockerfile deb nomlanishi kerak.
  • Har bir satr bitta ko'rsatma (INSTRUCTION) va uning argumentidan iborat bo'ladi.
  • Ko'rsatmalar katta harflar bilan yozilishi an'ana (FROM, WORKDIR, COPY va h.k.).
Docker CLI / Dockerfile 
# Oddiy Node.js ilovasi uchun Dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]
🐳 Docker Engine Chiqarishi:
💡 Dockerfile tufayli loyihangizni boshqa dasturchi yuklab olsa, hech qanday kutubxona o'rnatmasdan bitta buyruq bilan dasturni ishga tushira oladi.

Dockerfile Docker Mavzu #15

Dockerfile Asosiy Ko'rsatmalari

Dockerfile da ishlatiladigan eng asosiy kalit so'zlar vazifasi:

  • FROM — poydevor imidjni tanlash (barcha Dockerfile lar shu bilan boshlanadi).
  • WORKDIR — konteyner ichidagi asosiy ishchi jildni belgilash.
  • COPY — kompyuterdan konteynerga fayllarni ko'chirish.
  • RUN — imidjni qurish (build) vaqtida bajariladigan buyruqlar (paketlar o'rnatish).
  • ENV = — doimiy muhit o'zgaruvchilari.
  • EXPOSE — konteyner qaysi tarmoq portida tinglayotganini hujjatlashtirish.
  • CMD ["dastur", "arg"] — konteyner ishga tushganda bajariladigan asosiy start buyrug'i.
Docker CLI / Dockerfile 
# Python Flask ilovasi uchun Dockerfile
FROM python:3.11-slim
WORKDIR /usr/src/app
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
ENV PORT=5000
EXPOSE 5000
CMD ["python", "app.py"]
🐳 Docker Engine Chiqarishi:
💡 `RUN` imidjni yig'ish (build) paytida bajariladi, `CMD` esa tayyor imidjdan konteyner ishga tushirilganida ishlaydi.

docker build: Imidjni Yig'ish

Ilg'or Docker Mavzu #17

Multi-Stage Builds: Imidjni Ixchamlashtirish

Dasturni qurish (build) uchun og'ir SDK va kompilyatorlar kerak, lekin ishlatish (runtime) uchun ular mutlaqo ortiqcha yukdir. Multi-Stage bir nechta bosqich orqali imidj hajmini 1 GB dan 20 MB gacha qisqartiradi.

  • 1-bosqich (Builder): Barcha kodlarni kompilyatsiya qiladi va to'liq SDK dan foydalanadi.
  • 2-bosqich (Production): Juda kichik toza OS (masalan Alpine yoki Nginx) olib, faqat 1-bosqichdagi tayyor natija fayllarni (dist) ko'chirib oladi.
  • Imidj xavfsizroq bo'ladi (ichida manba kodlar va ortiqcha vositalar qolmaydi).
Docker CLI / Dockerfile 
# React ilovasi uchun Multi-Stage Dockerfile:
# 1-bosqich: Yig'ish
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# 2-bosqich: Faqat natijani tarqatish
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
🐳 Docker Engine Chiqarishi:
💡 Bu usul aynan React, Vue, Go, Rust va Java ilovalarida eng ajoyib samara beradi.

Saqlash Docker Mavzu #18

Docker Volumes: Doimiy Ma'lumotlar

Konteynerlar o'chirilganda ularning ichidagi barcha fayllar ham yo'qolib ketadi (stateless). Ma'lumotlar bazasi (Postgres, MongoDB) kabi doimiy saqlanishi shart bo'lgan fayllar uchun Volume ishlatiladi.

  • docker volume create — yangi disk hajmi yaratish.
  • docker volume ls — barcha volume larni ko'rish.
  • -v volume_nomi:/ichki/manzil — konteynerga bog'lash.
  • Konteyner butunlay o'chirib tashlansa ham, Volume dagi barcha ma'lumotlar zararsiz saqlanib qoladi.
Docker CLI / Dockerfile 
# PostgreSQL bazasini Volume bilan ishga tushirish
docker volume create pgdata
docker run -d \
  --name db \
  -v pgdata:/var/lib/postgresql/data \
  -e POSTGRES_PASSWORD=root \
  postgres:16-alpine
🐳 Docker Engine Chiqarishi:
💡 Konteynerni o'chirib, yangi versiyasini ishga tushirsangiz ham barcha ma'lumotlar o'z joyida turadi.

Dasturlash Docker Mavzu #19

Bind Mounts: Kodni Jonli Ulash

Dasturchi o'z kompyuteridagi faylni o'zgartirgan zahoti konteyner ichida ham darhol o'zgarishi (Hot Reload) uchun Bind Mount ishlatiladi.

  • -v /kompyuterdagi/yo'l:/konteynerdagi/yo'l — to'g'ridan-to'g'ri papkani ulash.
  • Har safar kodni o'zgartirganda yangitdan docker build qilish zaruratini yo'qotadi.
  • Mahalliy dasturlash muhiti (Development) uchun ideal.
Docker CLI / Dockerfile 
# Joriy papkani konteyner ichiga ulash (-v $(pwd):/app)
docker run -d -p 3000:3000 -v $(pwd):/app -w /app node:20-alpine npm run dev
🐳 Docker Engine Chiqarishi:
💡 Kodni VS Code da saqlashingiz bilan konteyner ichidagi nodemon yoki vite uni bir zumda qayta yuklaydi.

Tarmoqlar Docker Mavzu #20

Docker Networks: Konteynerlar Tarmoqlari

Konteynerlarning o'zaro bir-biri bilan xavfsiz gaplashishi uchun virtual tarmoqlar.

  • docker network create — yangi virtual bridge tarmoq yaratish.
  • Bitta tarmoqdagi konteynerlar bir-birining IP manzilini bilishi shart emas — ular konteyner nomi orqali to'g'ridan-to'g'ri bog'lana oladi (avtomatik DNS).
  • Masalan, Node.js konteyneri bazaga postgres://db:5432 orqali bemalol ulana oladi.
Docker CLI / Dockerfile 
# Umumiy tarmoq yaratib, ikkita konteynerni ulash
docker network create my-net
docker run -d --name my-db --network my-net postgres:16-alpine
docker run -d --name my-app --network my-net my-node-app
🐳 Docker Engine Chiqarishi:
💡 Tashqi dunyoga port ochmasdan turib ham (masalan, bazani tashqariga yopib) konteynerlarni o'zaro bog'lash mumkin.

Docker Compose Nima? Ko'p Konteynerli Tizimlar

Haqiqiy loyihalarda bitta emas, bir nechta konteynerlar (Frontend, Backend API, PostgreSQL, Redis) birgalikda ishlashi kerak bo'ladi. Ularning barchasini bitta fayl bilan boshqarish vositasi Docker Compose deb ataladi.

  • Bitta buyruq orqali butun loyihaning barcha qismlari birvarakayiga ishga tushadi.

# Docker Compose versiyasini tekshirish
docker compose version
🐳 Docker Engine Chiqarishi:
💡 Zamonaviy Docker da `docker-compose` defis bilan emas, `docker compose` bo'sh joy bilan yoziladi.

Compose Docker Mavzu #22

docker-compose.yml Fayli Strukturasi

Loyiha ildizida joylashuvchi docker-compose.yml faylining namunaviy tuzilishi.

  • services: — loyihadagi barcha mikroservislar ro'yxati.
  • image: yoki build: — qaysi imidjdan foydalanish yoki qayerdan build qilish.
  • ports: — tashqi va ichki portlar bog'lanishi.
  • environment: — muhit o'zgaruvchilari.
  • depends_on: — qaysi servis birinchi bo'lib ishga tushishi kerakligi.
Docker CLI / Dockerfile 
# docker-compose.yml namunasi:
version: '3.8'

services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgres://user:pass@db:5432/appdb
    depends_on:
      - db
      - redis

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: pass
      POSTGRES_DB: appdb
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine

volumes:

Compose Docker Mavzu #23

Docker Compose Asosiy Buyruqlari

Ko'p konteynerli ilovalarni bitta tugma bilan boshqarish.

  • docker compose up -d — barcha servislarni yig'ib, orqa fonda ishga tushiradi.
  • docker compose down — barcha konteyner va tarmoqlarni to'xtatadi va o'chiradi (xotira/volume larni saqlab qoladi).
  • docker compose down -v — volume lar bilan birga barcha ma'lumotlarni tozalab o'chiradi.
  • docker compose logs -f — barcha servislarning loglarini bitta oynada ko'rsatadi.
  • docker compose restart — barcha servislarni qayta ishga tushirish.
Docker CLI / Dockerfile 
# Loyihani ishga tushirish va to'xtatish
docker compose up -d
docker compose ps
🐳 Docker Engine Chiqarishi:
💡 Dasturchi kompyuteriga yangi kelgan xodim faqat `docker compose up -d` yozish orqali butun murakkab tizimni bir lahzada ishlatib keta oladi.

Xavfsizlik Docker Mavzu #26

Docker Eng Yaxshi Amaliyotlari va Xavfsizlik

Production darajasidagi ishonchli va xavfsiz Docker imidjlarini yaratish qoidalari.

  • 1. Doim .dockerignore faylidan foydalaning: node_modules, .git va maxfiy .env fayllarini imidjga kiritmang.
  • 2. Root foydalanuvchidan voz keching: Xavfsizlik uchun Dockerfile oxirida alohida past huquqli foydalanuvchi yarating (USER node).
  • 3. Ixcham imidjlar tanlang: Debian (1 GB) o'rniga Alpine (5 MB) yoki Slim versiyalardan foydalaning.
  • 4. Keshni to'g'ri tartiblang: Tez-tez o'zgaruvchi kodlarni Dockerfile ning oxiriga, kam o'zgaruvchi kutubxona o'rnatishlarini (package.json) yuqoriga qo'ying.
Docker CLI / Dockerfile 
# Xavfsiz production Dockerfile namunasi:
FROM node:20-alpine
WORKDIR /app
# Bog'liqliklarni keshdan foydalanish uchun alohida ko'chiramiz
COPY package*.json ./
RUN npm ci --only=production
COPY . .
# Root huquqlarini bekor qilamiz
USER node
EXPOSE 3000
CMD ["node", "server.js"]
🐳 Docker Engine Chiqarishi:
💡 Ushbu qoidalarga rioya qilish serverlaringizni xakerlik hujumlaridan himoya qiladi va deploy tezligini oshiradi.
